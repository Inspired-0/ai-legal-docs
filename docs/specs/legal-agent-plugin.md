# Плагин юридического помощника

Обновлено: 2026-10-31. Статус: автономность, DOCX и полный охват claude-for-legal подтверждены;
упаковка и выполнение процедур требуют реализации и испытаний.
Основание: [концепция](modular-legal-platform.md), [исследование](../investigations/modular-legal-platform.md).

## Цель

Пользователь устанавливает плагин в Codex или Claude Code и получает помощника,
который собирает обстоятельства, работает с материалами дела, готовит и проверяет
документы. Собственная IDE и аккаунт нашего MCP для этих задач не обязательны.
Модель и исполнение предоставляет выбранный хост.

Плагин работает с материалами пользователя: составляет карту фактов,
находит противоречия, проверяет документ по заданному стандарту и готовит проект.
Подключение правового MCP добавляет поиск норм РФ, чтение редакций и проверку цитат.
Допускаются бесплатные официальные сайты, источники хоста и другие разрешённые
адаптеры с сохранением происхождения. Наш MCP является одной из интеграций. Платные
правовые источники исключены; доступ не считается настроенным лишь по наличию URL.

## Основные процедуры

| Процедура | Вход | Проверяемый результат |
| --- | --- | --- |
| Настройка практики | Роль, тип задач, сторона сделки, стандарты и разрешённые источники | Краткий редактируемый профиль; отсутствующие предпочтения не выдуманы |
| Начало дела | Цель и обстоятельства, документы при наличии | Факты с происхождением, вопросы, ограничения, выбранная папка дела |
| Подготовка документа | Согласованные обстоятельства, шаблон или требования к содержанию | Проект, список допущений/пропусков, формальные проверки |
| Проверка документа | Документ, цель проверки, стандарт пользователя | Замечания с привязкой к тексту, основаниями и предложениями исправлений |
| Проверка правового вывода | Задача, факты, проект, источники | Отдельный отчёт по утверждениям и неразрешённым вопросам |
| Настройка процедуры | Инструкция или завершённый пример | Версия навыка без данных исходного клиента, пробный запуск на другом деле |

Владелец выбрал создание и проверку договоров с DOCX первым сценарием. Целевой плагин
включает также весь набор claude-for-legal: корпоративные и трудовые задачи,
персональные данные, продукт/рекламу, регуляторную работу, ИИ, интеллектуальные права,
споры, клинику, обучение и управление навыками. Функции переносятся по этапам с
адаптацией к РФ; договорный пилот не закрывает весь объём.

Полный [каталог](../investigations/claude-for-legal-capabilities.md) содержит исходные
150 файлов навыков, 10 агентов и зависимости. Он является перечнем для сопоставления
и приёмки, а не заявлением о работающем продукте. Платный CoCounsel исключён;
собственный автономный исследователь отложен. Планирование исследования и работа
с источниками основным агентом сохраняются как обычные процедуры плагина.

## Режимы доказательств

Без внешнего правового источника проверяются содержание и согласованность полученных
материалов, формальные поля и расчёты. Загруженный пользователем текст закона можно
цитировать как предоставленный материал с неизвестной внешней актуальностью.
Модельная память не заменяет проверку действующей нормы.

С MCP агент получает доказательства по [контракту цитирования](legal-citations.md).
Для подбора регулирования и поиска ограничений он может вызвать составные инструменты
[MCP](legal-mcp.md#составной-поиск-и-граница-с-агентом), передав выбранную формулировку,
аспекты вопроса и необходимые обстоятельства. Плагин организует уточнение фактов
и оценку применимости; запрет или разрешение не выводятся из ранга и пустой выдачи.
При работе с другим источником сохраняется процедура получения оснований через
доступные ему средства; наличие наших составных инструментов не условие установки.
Проверяющий работает в отдельном контексте с теми же существенными фактами и самостоятельно
получает источники. Хостовый адаптер должен поддержать этот запуск. Если отдельная
проверка или получение права недоступны, результат остаётся непроверенным; повторное
чтение основным агентом нельзя обозначать независимым заключением.

Структурная проверка DOCX, совпадение цитаты и юридический вывод имеют разные статусы.
Имена `done`, `needs_input`, `failed` прежнего конвейера сохраняются при его вызове,
но `done` не означает юридическое одобрение документа.

## Состав поставки и повторное использование

Общая библиотека содержит навыки, примеры, шаблоны и локальные инструменты. Хостовые
манифесты и адаптер запуска проверяющего отделены от правовых процедур. Установка не
перезаписывает чужие инструкции и не включает неизвестные внешние подключения.

Из [claude-for-legal](https://github.com/anthropics/claude-for-legal) поэтапно адаптируется
полный каталог основных процедур, начиная с договоров. Общие интервью и профили можно
объединять, сохраняя соответствие функциям. Российские юридические критерии требуют
собственной разработки и последующей проверки юристами. Конкретные перенесённые файлы,
исходная версия, лицензия и исключённые зависимости фиксируются отдельно.

Из текущего репозитория используются схема полей, детерминированные расчёты,
`docxtpl`-рендер и проверки. Синтетический шаблон остаётся демо. Для новых рабочих
шаблонов нужны собственные версии; юридическая приёмка проходит позже. До неё шаблон
не обозначается юридически проверенным. Свободная генерация текста
агентом и детерминированное заполнение шаблона являются разными процедурами.
Редактирование произвольного Word с сохранением всех слоёв и tracked changes
не считается готовым следствием наличия `python-docx`.

Договорный сценарий включает новый DOCX из обстоятельств/шаблона, чтение существующего
файла, замечания с адресами, исправленную копию и redline с комментариями. Для заявленного
набора файлов проверяются таблицы, нумерация, колонтитулы, сноски, прежние комментарии
и принятие/отклонение tracked changes. Неподдержанные конструкции явно отмечаются
до изменения файла. Сторонний `docx skill`, на который ссылается upstream, сам по себе
не является частью нашей поставки; инструмент должен быть доступен и испытан в обоих хостах.

Реестры и watcher работают с локальными файлами либо доступными интеграциями. Для
автоматического запуска нужен проверенный планировщик хоста/отдельный runtime. Функции,
которым нужны судебные или патентные данные, не считаются выполненными по одному наличию
федерального законодательства в MCP. Отправка сообщений, подпись и внешняя синхронизация
проверяются отдельно от подготовки локального документа.

## Файлы и данные

Предлагаемая структура дела: `matter.md`, `facts.json`, `sources/`, `drafts/`,
`reviews/`, `outputs/`. Это рабочие имена; путь выбирает пользователь.
Профиль практики и стандарты доступны только по разрешению. Между делами нельзя
автоматически переносить факты или клиентские материалы.

Первый выпуск использует обычные права файловой среды Codex/Claude Code. Разделение
папок и правила навыка не гарантируют изоляцию от самого хоста. Переданные агенту
документы обрабатываются по настройкам этого хоста; наш MCP не получает их для
общего индексирования. Реестр псевдонимов в этом режиме отсутствует.

Защищённый режим позже требует локальной подготовки копий, технического запрета
чтения оригиналов агентом и контроля истории/поиска/экспорта. Требования описаны
в [отдельной спецификации](local-pseudonymization.md). SQLite для установки плагина
не нужна; необходимость локального индекса материалов решается по реальным объёмам.

## Приёмка

- Установка в чистые профили обоих хостов; первый документный сценарий с отключённым MCP.
- Настройка практики не блокирует простую первую задачу длинным обязательным интервью.
- Недостающие факты дают вопросы или явные пропуски, а не вымышленные реквизиты.
- Новый файл создан, расчёты воспроизводимы, исходник сохранён; неподдержанный DOCX
  не объявляется корректно отредактированным.
- Без правового источника нет заявления о проверенной актуальности норм; с ним
  цитаты разрешаются в реальные доказательства.
- Отчёт проверяющего связан с версией; после существенной правки он устаревает.
- После обновления пакета доступны прежние дела, стандарты и пользовательские навыки.
- Повтор процедуры на другом деле не переносит в него факты первого.
- Для каждой позиции каталога есть результат испытания либо явно незакрытая зависимость.
  Только договорный пилот нельзя обозначить полным переносом claude-for-legal.
- DOCX с комментариями и tracked changes корректно открывается, а принятие/отклонение
  правок даёт ожидаемый текст; требующие таблиц процедуры создают проверяемый XLSX/CSV.
- Расписание подтверждено реальным запуском без активного диалога и восстановлением
  после пропуска. Ручной запуск не засчитывается как проверка автоматического мониторинга.

Сначала испытания используют синтетические данные. Файлы реальных клиентов в
репозиторий и тестовые фикстуры не добавляются. Юристы проверяют результаты позже;
технический выпуск до этого имеет явный статус без юридической приёмки.
