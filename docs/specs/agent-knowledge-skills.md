# Агентные процедуры, правовой MCP и навыки

Обновлено: 2026-10-31. Статус: требования и предлагаемая реализация в
[модульной концепции](modular-legal-platform.md).
Правовой корпус и поиск принадлежат [MCP](legal-mcp.md), процедуры, работа с делом
и проверяющий принадлежат [плагину](legal-agent-plugin.md), интерфейс подключений
и применения правок относится к [IDE](legal-ide-shell.md).

## Универсальность

Продукт принимает цель и обстоятельства клиента, не только файл или выбранный вид договора.
Агент уточняет юрисдикцию, даты, роли, желаемый результат и ограничения; различает утверждения
клиента, факты из документов, предположения и неизвестное. Он строит исследование, предлагает
варианты действий и подготавливает документы с проверяемыми источниками.

Общий цикл: задача → карта фактов/вопросов → поиск доказательств → план → навык/инструменты →
проект результата → программные проверки → отдельный агент-проверяющий → исправления →
review юристом. Специализация выбирается по задаче, а не жестко
зашивается в приложение. IT и закупки по 44-ФЗ/223-ФЗ сохраняются как накопленные
профили исследования; первым сценарием плагина выбраны создание и проверка договоров с DOCX.
Не объявлять все отрасли одинаково проверенными: хранить матрицу юрисдикций, сценариев и качества.

## Поиск и источники по модулям

RAG выбирает доказательства для ответа на правовой вопрос. Правовой RAG реализуется
в MCP. Самостоятельный плагин работает с предоставленными материалами и без нашего
сервера; подключённый правовой источник расширяет проверку. Для рассуждения и
применимости нужны отдельные процедуры.

В MCP общая процедура объединяет поиски, получает контекст и раскрывает доступные
отсылки. `find_legal_framework` подбирает регулирование по вопросу;
`find_restrictions` ищет основания ограничений по выбранной формулировке. Агент может
передать аспекты вопроса и обстоятельства, затем сопоставляет доказательства с фактами.
Серверные признаки типа нормы и основания отбора не заменяют эту оценку.
Обычный чат использует инструменты без нашего плагина и отдельного исследователя.
Контракт и статусы: [составной поиск](legal-mcp.md#составной-поиск-и-граница-с-агентом).

| Пространство | Что хранит/ищет | Правило |
| --- | --- | --- |
| Законодательство | Нормы, редакции, изменения и связи в MCP | Федеральный охват первого выпуска; поиск по реквизитам и смыслу, даты и покрытие |
| Судебная практика | Возможное расширение корпуса MCP | Отдельный тип источника; не входит в обязательный первый охват |
| Материалы клиента | Факты, документы, переписка, прошлые версии в среде хоста | Обычный файловый режим первого плагина; защищённый режим позже |
| Знания организации | Стандарты, образцы, проверенные позиции | Происхождение и версия; не выдавать предпочтение компании за закон |

Гибридный поиск: точные реквизиты/лексика плюс семантика; фильтры по доступу, юрисдикции и дате;
переранжирование и получение соседних положений, исключений и определений. Ссылки и цитаты
строятся из реально полученных фрагментов. Пустая выдача не доказывает отсутствия нормы.
MCP обновляет индекс права и журнал. Плагин/IDE при повторной проверке замечают
изменившиеся основания и помечают соответствующие выводы. Материалы клиента не
индексируются в общем правовом корпусе. Организационные образцы используются в рамках
доступа и текущей задачи, без переноса фактов других клиентов. Для будущего защищённого
режима действуют дополнительные правила [псевдонимизации](local-pseudonymization.md).

Контракт [точного цитирования](legal-citations.md) задает неизменяемые редакции, структурные
единицы и доказательства; совпадение цитаты и юридическая применимость проверяются отдельно.

## Отдельный агент-проверяющий

Проверка обязательна для выдаваемых правовых выводов и предложений юридически значимых правок.
Первый агент исследует задачу и готовит проект. Второй работает в отдельном контексте:
получает задачу, разрешённые факты, проект, перечень утверждений и ссылки на доказательства,
самостоятельно получает источники и ищет исключения/противоречия. Он не наследует обсуждение
первого агента и не ограничивается пересказом его подборки. При этом обе роли имеют одинаковый
доступ к существенным фактам дела и одну политику работы с данными.

Этот цикл организует плагин и затем IDE. Самостоятельный MCP возвращает источники
и программные проверки, но не может принудить произвольный подключённый чат
запускать независимого проверяющего. При недоступности источников или отдельного
контекста плагин явно оставляет правовой результат непроверенным.

У проверяющего только чтение и поиск: нет права самостоятельно применять правки к оригиналу,
подтверждать результат за юриста или менять правила проверки. Контроллер связывает вердикт
с точной версией результата, документов, фактов и источников. Исправленный проект проверяется
повторно. Обязательные программные проверки невозможно отменить решением модели.

Подробный [контракт проверки](legal-citations.md#проверяющий-агент-и-цикл-исправлений) определяет
статусы отдельных выводов, повторные попытки и приемку. Согласие моделей не является
доказательством достоверности. Одна модель в двух отдельных ролях допустима для прототипа;
другую модель можно сравнить на размеченном наборе, без обещания независимости ошибок.
Второй провайдер допускается только разрешённым маршрутом обработки данных выбранного режима.

## Самостоятельный выпуск правовой базы

MCP предоставляет законодательство РФ без ручной загрузки пользователем кодексов.
Используется собственный обновляемый корпус из бесплатных официальных источников;
платные правовые данные исключены владельцем. Адаптеры сохраняют происхождение,
редакции и условия получения/хранения. Плагин подключает MCP по желанию пользователя.

Для первого MCP проверить федеральное покрытие, исторические
редакции, срок обновления, стабильные фрагменты и право отображения/передачи выбранной модели.
Практика, комментарии и международное право не автоматически входят в слово «законодательство».
Полнота и сроки обновления определяются проверкой каналов и каталога.
Составить измеримую карту покрытия до обещания полной базы.

Один или несколько источников должны закрыть согласованное покрытие до выпуска MCP.
Тестовый корпус годится для прототипа, но не выполняет требование владельца.
Каналы, VPS и ограничения: [исследование](../investigations/legal-mcp-vps.md).
Юридическая оценка проходит позже; техническая загрузка и проверки её не ждут.

## Конструктор навыков

Навык — версионируемая процедура решения задачи, а не набор актуальных законов внутри промпта.
Сгенерировать черновик можно из текстовой инструкции, пользовательского образца или завершенной
работы. Примеры: проверить лицензионный договор; собрать матрицу требований закупки;
подготовить проект документа по стандарту компании; объяснить основания выбранных пунктов.

Предлагаемый состав навыка:

- Название, цель, условия применения и неподдержанные случаи.
- Входные данные, обязательные вопросы и ожидаемый формат результата.
- Порядок действий, разрешенные инструменты и требуемые правовые источники.
- Проверки качества, критерии отказа/эскалации и примеры правильного результата.
- Версия, автор, область доступа и журнал изменений.

Путь пользователя: «создать навык» → описание/пример → уточнения → сгенерированная процедура →
просмотр → пробный запуск на копии → проверка → активация. Доступен быстрый старт по шаблону.
Сохранить успешную работу как навык можно, но исходные имена, факты дела и секреты не должны
попадать в общий шаблон; ссылки на стандарты привязываются к правам организации.

Для первого плагина навыки декларативные и вызывают существующие инструменты; произвольный сгенерированный
код автоматически не исполняется. Создание навыка не расширяет доступ к файлам/сети и не отключает
выбранную политику данных. Версию нельзя незаметно заменить во время выполнения. Публикация в общую
библиотеку — отдельное действие; навык из внешнего документа не становится доверенной инструкцией.
Актуальные нормы навык получает через подключённый источник при запуске. Без такого
источника он не заявляет проверенную актуальность текста из памяти или загруженного файла.

## Приемка

- Задача без документов приводит к полезным уточнениям и плану, а не требованию загрузить договор.
- На одном ядре работают разные профили; неизвестный профиль не получает ложную отметку проверенного.
- Ссылка ведет к полученному фрагменту нужной редакции; источник и стандарт компании различаются.
- Правовой результат проходит отдельного проверяющего; непроверенный/оспоренный вывод не
  получает статус проверенного. Изменение результата аннулирует вердикт соответствующей версии.
- Из инструкции создается навык, проходит тестовый запуск и повторяет результат на другом деле.
- Сохранение/экспорт навыка не раскрывает данные исходного дела или реестр псевдонимов.
- Несанкционированный инструмент, устаревшая версия, подложная инструкция и ошибочная цитата
  обнаруживаются; есть отзыв версии и откат. Выполнение останавливается по бюджету/отмене.

Эти условия требуют разработки и испытаний; текущий Python/DOCX демо их не реализует.
