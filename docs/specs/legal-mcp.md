# Правовой MCP для законодательства РФ

Обновлено: 2026-10-31. Статус: требования первого самостоятельного модуля;
составной поиск на сервере и оценка применимости у агента подтверждены владельцем.
Имена полей, JSON-схемы и стек требуют проверки перед реализацией.
Основание: [концепция](modular-legal-platform.md), [исследование](../investigations/modular-legal-platform.md),
[ADR-0003](../decisions/ADR-0003-compound-legal-search.md).

## Цель и границы первого выпуска

Пользователь подключает общий сервер к ChatGPT или Claude и получает федеральные
нормы по реквизитам, словам или смыслу вопроса, подбирает регулирование деятельности
или отношений и ищет основания ограничений по формулировке. Он читает конкретную
редакцию и узнаёт об изменениях. Для этого не нужны наш плагин, IDE или локальная база права.

Охват включает кодексы, федеральные законы, постановления и ведомственные акты;
реестр должен также явно учитывать включённые виды президентских и иных федеральных
актов. Список органов, видов и доступных периодов оформляется в манифесте покрытия.
Пилот на нескольких кодексах предшествует широкому выпуску и не подменяет его.
Региональные/муниципальные акты, практика судов, разъяснения, проекты и новости
имеют отдельные типы и пока не входят в обязательный корпус первого выпуска.

MCP хранит публичный правовой корпус. Файлы договоров и дела пользователя в его
серверной БД не размещаются. Инструмент может получить выбранную формулировку и
необходимые обстоятельства как аргументы запроса; они не попадают в общий индекс права.
Поиск источников, разбор структуры, сбор связанных положений и сравнение редакций
выполняются на сервере. Подключённый агент уточняет обстоятельства, оценивает
применимость и формулирует юридический вывод. Собственный исследовательский агент
отложен; генеративная модель на сервере и MCP sampling в первый выпуск не требуются.

## Основные сценарии

| ID | Сценарий | Результат |
| --- | --- | --- |
| MCP-U1 | Найти акт или статью по реквизитам | Найденный акт, точный структурный адрес, доступные редакции |
| MCP-U2 | Подобрать акты и нормы по описанию сегмента, отношений или проблемы | Подборка по аспектам запроса с текстовыми основаниями, связанными положениями, датами и пробелами покрытия |
| MCP-U3 | Прочитать норму в заданной редакции или на дату | Текст с соседними положениями; при неопределённости явный статус и варианты |
| MCP-U4 | Сравнить редакции | Добавленные, изменённые и исключённые единицы с обеими версиями |
| MCP-U5 | Получить изменения с предыдущего просмотра | Страницы журнала, устойчивый курсор, ссылки на акты/редакции |
| MCP-U6 | Проверить приведённую цитату | Результат проверки текста, адреса и версии без автоматического вердикта о применимости |
| MCP-U7 | Найти запреты и ограничения для условия или предполагаемого действия | Кандидаты запрещающих и обязывающих норм, условий разрешения и исключений; оценка применимости остаётся у агента |

| ID | Требование |

| MCP-03 | Точный, текстовый и семантический поиск; объединение выдач выбирается измерением |
| MCP-04 | Неизменяемые снимки, редакции и структурные адреса; явная версия парсера и индекса |

| MCP-07 | Как минимум ежедневный цикл обновления и наблюдения; догрузка пропусков и поздних публикаций |
| MCP-08 | Журнал публикаций, редакций и изменений метаданных; повтор обработки не создаёт дубли |
| MCP-09 | Программная проверка цитаты и принадлежности версии; старое доказательство воспроизводится после обновления |
| MCP-10 | Видимая свежесть, пробелы, ошибки источников и доля недоступного содержания в заданном каталоге |
| MCP-11 | Изоляция доступа к настройкам/учётным данным пользователей; минимизация и отдельная политика хранения запросов |
| MCP-12 | Восстановление после сбоя без публикации половины редакции или рассогласованных поисковых индексов |
| MCP-13 | Составной подбор регулирования: объединение поисков по вопросу и переданным аспектам, группировка по актам, получение контекста и доступных отсылок |
| MCP-14 | Поиск возможных ограничений по формулировке: прямые запреты, обязательные требования, условия разрешения и исключения; тип нормы имеет основание и допускает неопределённость |
| MCP-15 | Ответ составного поиска показывает выполненные запросы, версии процедуры/корпуса, границы поиска, незавершённые шаги и достигнутые лимиты |
| MCP-16 | Найденные кандидаты, состояние выполнения, покрытие, временная проверка и применимость имеют отдельные статусы; пустая выдача не является разрешением или доказательством отсутствия нормы |

Для первого выпуска предлагаем клиентам только чтение. Загрузка, переиндексация и
управление источниками доступны оператору через отдельный административный интерфейс.
Значение `readOnlyHint` описывает инструмент клиенту, права ограничивает сам сервер.

## Предлагаемый контракт инструментов

Названия рабочие. До реализации фиксируются JSON-схемы, ошибки и версия контракта.

| Инструмент | Основные аргументы | Содержимое результата |
| --- | --- | --- |
| `search_law` | `query`, `filters`, `as_of?`, `cursor?` | Кандидаты актов/норм, `evidence_id` для полученного текста, режим поиска, свежесть и ограничения |
| `find_legal_framework` | `query`, `context?`, `aspects?`, `filters?`, `as_of?`, `cursor?` | Акты/нормы по вопросу, основания совпадений, связанные положения, незакрытые аспекты и границы поиска |
| `find_restrictions` | `formulation`, `context?`, `aspects?`, `filters?`, `as_of?`, `cursor?` | Кандидаты ограничений с цитатами, признаками типа нормы, контекстом и исключениями; без вердикта о допустимости |
| `get_law_text` | `act_id`, `edition_id`, `unit_path?`, `cursor?` | Текст нормы или страницы акта, контекст структуры, ссылка на источник |
| `list_editions` | `act_id`, `cursor?` | Известные редакции, основания изменений, доступность текста и семантика дат |
| `compare_editions` | `act_id`, `from_edition`, `to_edition`, `cursor?` | Структурный/текстовый diff; неподтверждённое соответствие пунктов отмечено |
| `get_changes` | `since?`, `cursor?`, `filters?` | События с ID и временем обнаружения, обе редакции при наличии, следующий курсор |
| `check_citation` | `evidence_id`, `quote` | Совпадение текста, границ и редакции; применимость отдельным статусом |
| `get_corpus_status` | `filters?` | Состав каталога, периоды, последняя успешная проверка, отставание и пробелы |

Точный поиск реквизита входит в `search_law`; при неоднозначности возвращаются кандидаты.
Пара `search`/`fetch` как адаптер для специальных режимов клиентов добавляется только
если испытание соответствующего режима подтвердит необходимость.

Ответ с текстом содержит `schema_version`, `corpus_generation`, идентификаторы акта,
редакции и единицы, `evidence_id`, цитату/диапазон, URL источника, время получения,
качество извлечения, статус временной проверки и предупреждения. Это разные поля;
одна общая оценка confidence не заменяет их. Подробная модель: [точные ссылки](legal-citations.md).

`as_of` означает запрошенную дату действия, а не произвольное сравнение с датой загрузки.
Если сервер не располагает достаточными данными, он сообщает `temporal_status=unknown`
или неоднозначность. `source_current` означает только метку источника. Для нормы с
особыми переходными условиями дата акта целиком недостаточна.

## Составной поиск и граница с агентом

Оба инструмента работают в обычном ChatGPT/Claude с подключённым MCP. Плагин может
добавить процедуру уточнения фактов и проверки вывода, но для самого поиска не нужен.
`search_law` сохраняется для точечного поиска и повторной проверки подборки.
`check_citation` проверяет совпадение текста и версии, не допустимость формулировки.

### Входные данные

Достаточно одного вопроса или формулировки. Необязательный `context` содержит роли
участников, вид отношений, территорию, известные факты и явно обозначенные неизвестные.
Агент отделяет факты от предположений. Сервер не угадывает статус участника или дату
отношений и не сужает по ним поиск без переданного основания. Дата задаётся через
`as_of`; без неё ответ отмечает отсутствие запрошенной даты действия.

`aspects` позволяет передать несколько отдельных вопросов с ID. Они задают ветви
поиска, а не утверждают полный перечень правовых вопросов дела. Без них сервер ищет
по исходному вопросу; самостоятельную юридическую декомпозицию выполняет агент.
Дополнительные обстоятельства и повторный вызов уточняют подборку.

Синтетические примеры входа: «Какие акты могут регулировать сервис онлайн-обучения
для физических лиц?» и «Исполнитель вправе изменить стоимость услуги в любой момент».
Для второго примера поиск получает выбранное условие и существенный контекст,
без передачи всего договора и ненужных реквизитов. Политика хранения запросов из
MCP-11 распространяется на эти аргументы и технические логи. Псевдонимизация
не заявляется свойством обычного подключения.

### Процедура на сервере

1. Проверить вход, зафиксировать фильтры, запрошенную дату и опубликованное поколение
   корпуса. Неизвестные обстоятельства сохранить явно.
2. Выполнить точный, текстовый и семантический поиск по исходному запросу и аспектам.
   Нормализация и расширения по версионируемым словарям отражаются в ответе.
   Для ограничений дополнительно искать формулировки запрета, обязанности, согласия
   и исключения; наличие ключевого слова не служит единственным фильтром.
3. Объединить выдачи выбранным по измерениям способом. Удалить повторы одной единицы
   в одной редакции, сохранив основания попадания. Для MCP-U2 группировать результат
   по актам и переданным аспектам, чтобы повторы фрагментов одного акта не заполняли подборку.
4. Получить полные положения, доступный структурный контекст и извлечённые отсылки.
   Включить найденные определения, условия действия, исключения и переходные положения.
   У каждого перехода сохранить исходную цитату и адрес назначения; неоднозначная
   или недоступная ссылка остаётся неразрешённой. Полнота связей не предполагается.
5. Вернуть доказательства, основания отбора и состояние поиска. Число запросов,
   объём контекста, глубина переходов и время ограничены конфигурацией. Достигнутый
   лимит или сбой виден вместе с невыполненной частью. Страницы выдачи привязаны
   к одному запросу, версии процедуры и поколению корпуса; истёкший курсор требует
   нового поиска и не переключается молча на новые данные.

Процедура использует поисковые модели, правила и структуру корпуса. Генерация
юридического заключения на сервере в неё не входит. Извлечённые ссылки можно хранить
рядом с реестром актов; отдельная графовая БД для этого не требуется.
Полный серверный анализ можно рассмотреть после пилота, если выяснится, какие задачи
агент не решает с полученными доказательствами. Пробелы корпуса и поиска оцениваются отдельно.

### Результат и статусы

Кандидат содержит акт, редакцию, структурный адрес, `evidence_id`, цитату, источник,
статус временной проверки и качество извлечения по общему контракту. Дополнительные поля:

| Поле | Смысл |
| --- | --- |
| `match_basis` | ID запроса/аспекта, способ поиска или явная отсылка, по которым найден кандидат; это основание отбора, не вывод о применимости |
| `context_evidence` | Полученные соседние и связанные положения со своими доказательствами и происхождением связи |
| `norm_type_hint` | Для ограничений: предполагаемый запрет, обязанность, условие разрешения, исключение, иной тип или `unknown`; текстовый признак и версия правила обязательны для автоматической метки |
| `missing_context` | Неизвестные, переданные клиентом или обнаруженные по проверяемым правилам профиля; полный перечень значимых фактов определяет агент |
| `unresolved_references` | Неоднозначные ссылки, отсутствующие тексты и положения вне корпуса с причинами |
| `search_scope` | Выполненные запросы/расширения, фильтры, дата, версии процедуры и корпуса, охваченные аспекты, доступность источников и лимиты |

Если правило не устанавливает тип нормы, возвращается `unknown` с найденным текстом.
Семантическая близость сама по себе не позволяет пометить норму прямым запретом.
Условия и исключения передаются цитатами; их связь с обстоятельствами объясняет агент.

У ответа три независимых статуса:

- `execution_status`: `completed`, `partial` или `failed`. `completed` означает
  завершение запланированной поисковой процедуры в указанном объёме. Сбой ветви,
  недоступность нужного текста по отсылке или обрезание процедуры лимитом дают `partial`;
  невозможность выполнить поиск даёт `failed`.
- `match_status`: `candidates_found`, `no_candidates` или `not_evaluated`.
  `no_candidates` допустим только при `completed`. При неполном выполнении без
  кандидатов возвращается `not_evaluated`; уже полученные кандидаты можно вернуть с `partial`.
- `applicability_status`: `not_assessed` для обоих инструментов. Агент оценивает
  применимость отдельно, даже когда текст и дата действия нормы проверены.

Покрытие корпуса и свежесть сохраняются отдельно от этих статусов. Завершённый поиск
не означает полного охвата законодательства. Отсутствие найденного запрета не даёт
значений «разрешено», «законно» или «ограничений нет». Недостающая практика судов,
региональные акты и иные исключённые типы источников видны в границах поиска.

## Обновление и хранение

Размещение на VPS подтверждено владельцем. Используются только бесплатные правовые
источники: официальные публикации, доступные редакции ЕБПИ и дополнительные официальные
каналы. Платный поставщик не используется для закрытия пробелов. При недоступном тексте
сервер сохраняет явный статус и повторяет получение; условия массового доступа проверяются
для каждого канала. Собственный исследовательский агент в первый объём не входит.

Внутри модуля отдельно работают MCP API и updater. Предлагаемые хранилища:
PostgreSQL для реестра/версий/журнала и поиска, файловое или объектное хранилище для
неизменяемых ответов и оригиналов. FTS/pgvector служат индексами, которые можно
перестроить по сохранённому корпусу. SQLite не требуется.

Событие обновления проходит состояния `observed`, `fetched`, `parsed`, `validated`,
`indexed`, `published`; ошибки и частичное содержание учитываются отдельно.
Текущая опубликованная версия переключается после проверки готовности данных.
Сбой до переключения оставляет доступной предыдущую версию и видимый статус отставания.
Повтор использует ключ источника/события и хеш; он не должен перезаписывать прежние
цитируемые снимки.

Для каждой редакции сохраняются исходные метаданные и история их наблюдений.
Изменение статуса при прежнем `redid` должно попасть в журнал. Текстовый diff не
выдаётся за юридическое заключение о последствиях поправки. Анализ связи изменения
с конкретным договором относится к агенту, имеющему материалы этого дела.

Расписание ежедневное. Показатели `last_attempt_at`, `last_success_at`,
`source_observed_at` и `indexed_at` разделены. Успех одного источника не скрывает
отказ другого. Период допустимого отставания и время запуска согласуются перед пилотом.
Мониторинг будущих дат не зависит только от появления нового опубликованного акта.

Исходная оценка VPS: 8 vCPU, 32 ГБ RAM, 300-500 ГБ NVMe с расширением, без обязательного
GPU. Для технического пилота рассматриваем 4 vCPU/16 ГБ. Оценка зависит от числа
фрагментов/редакций и CPU-инференса; [расчёт и план измерений](../investigations/legal-mcp-vps.md).

## Приёмка

Технический пилот включает следующие проверки без ожидания юридической разметки.
Правовую применимость, качество релевантности и полноту по выбранным вопросам юристы
проверяют позже, на отдельном этапе. До этого нет статуса юридически проверенной базы.

- MCP-U1…U7 выполняются в ChatGPT и Claude без плагина и IDE. Составные инструменты
  работают без серверной генеративной модели и без запроса MCP sampling у клиента.
- Есть согласованный федеральный каталог и отчёт доступности по видам/органам/периодам;
  технически проверены происхождение, полнота получения и видимость пробелов.
- Результаты поиска измерены на технической выборке с отдельной контрольной частью.
  Порог определяется до настройки на контроле; эта выборка не подменяет будущую разметку юриста.
- Подменённая цитата, ссылка на чужую редакцию и отсутствующий фрагмент отклоняются.
  Проверка совпадения с извлечённым текстом отделена от проверки правильности извлечения.
- Будущая редакция, неполный текст, неизвестная дата и недоступный источник дают явные
  статусы. Отсутствие выдачи не превращается в утверждение об отсутствии регулирования.
- Проверены повторный запуск, поздний документ, смена метаданных прежнего ID,
  остановка updater и восстановление; текущая выдача не смешивает поколения индекса.
- Старое доказательство доступно после обновления. Журнал читается с курсором без
  пропуска поздно обнаруженных событий.
- Зафиксированы установка, авторизация, резервная копия, восстановление и наблюдаемость.

Для MCP-U2/MCP-U7 техническая выборка включает следующие случаи. Ожидания сначала
проверяют механизм на синтетическом корпусе и происхождение реальных фрагментов;
правовую полноту и применимость оценивают юристы позже.

| Случай | Проверяемый результат |
| --- | --- |
| Несколько аспектов и актов | Видно, какие ветви выполнены; повторы одной единицы объединены, основания отбора сохранены |
| Запрет с исключением и определением в других положениях | Доступные ссылки раскрыты с доказательствами; неопределённые связи отмечены, исключение не отброшено из-за ранжирования |
| Отрицание или похожий текст | Одно слово «запрещается» и векторная близость не дают подтверждённый тип запрета; у метки есть текстовое основание и правило либо `unknown` |
| Неизвестные стороны, территория или дата | Сервер сохраняет неизвестное, не придумывает факты и не заявляет применимость |
| Будущая редакция, неизвестная дата действия | Временной статус не повышается из-за высокого ранга или совпадения текста |
| Завершённый поиск без совпадений | `completed`, `no_candidates`, `not_assessed`; охват виден, положительного вывода о допустимости нет |
| Сбой, недоступная отсылка, превышение лимита | `partial`/`failed` с причиной и полученной частью; отсутствие кандидатов не маскируется под успешную проверку |
| Пагинация при обновлении базы | Выдача сохраняет поколение и версию процедуры либо требует нового поиска; старые доказательства воспроизводятся |

Измеряются найденные акты и положения по аспектам, доступность связанного контекста,
доля неразрешённых отсылок, задержка и нагрузка составного вызова. Один `hit@k` по
статьям не оценивает весь сценарий. Порог и контрольная часть задаются до настройки;
результат RAG-пробы на двух актах не считается приёмкой этих инструментов.

Последующая юридическая приёмка: юристы проверяют выборку актов/редакций, применимость
на дату, релевантность поиска, пропущенные запреты/исключения и ошибочные метки ограничений.
Порог и контрольный набор фиксируются до настройки по юридической оценке.
Этот этап не блокирует разработку API, загрузку
и ресурсные измерения или техническую работу над следующими модулями.

## Открыто до первого выпуска

Дата начала исторического охвата, глубина прежних редакций, численный критерий
широты/качества, бюджет инфраструктуры, провайдер VPS, модель доступа и условия
массовой работы с бесплатными источниками. Ни срок,
ни обещание полного федерального корпуса пока не подтверждены.
