# AI Legal Docs: контекст продукта

Продукт развивается как три самостоятельных модуля: правовой MCP, плагин юридического
помощника и IDE. Разработка идёт от модуля к модулю; MCP и плагин дают пользу до
появления собственной IDE. Направление изменено владельцем 30.10.2026.

| Модуль | Пользовательский результат | Первая поставка |
| --- | --- | --- |
| [Правовой MCP](specs/legal-mcp.md) | Поиск и чтение норм РФ, редакции, проверка цитат, журнал изменений | Общий сервер для ChatGPT и Claude; широкий федеральный корпус, ежедневное обновление из newsBot |
| [Плагин](specs/legal-agent-plugin.md) | Работа с обстоятельствами и документами в обычном агенте | Установка в Codex/Claude Code; полезен без нашего MCP и IDE |
| [IDE](specs/legal-ide-shell.md) | Документы, диалог, источники и принятие правок в одном рабочем пространстве | Третий этап с подключением модулей и других интеграций |

Плагин сначала работает с файлами в среде агента. Защищённый режим с локальной
псевдонимизацией будет отдельным развитием. Дела пользователей не входят в общий
правовой корпус. Юридические ссылки сохраняют происхождение и редакцию; совпадение
цитаты не означает подтверждённой применимости нормы.

Плагин охватывает весь набор процедур claude-for-legal; первым сценарием владелец
выбрал создание и проверку договоров с DOCX. Собственный исследовательский агент
отложен. MCP запускается на VPS и использует только бесплатные правовые источники.
Юристы проверят результаты позже; технические испытания не объявляются юридической приёмкой.

[Концепция](specs/modular-legal-platform.md) задаёт границы,
[дорожная карта](plans/active/modular-platform-roadmap.md) порядок,
[интервью](investigations/modular-platform-interview.md) принятые и открытые решения.
Стек, источники и повторное использование сравниваются в
[исследовании](investigations/modular-legal-platform.md).
Полный [каталог функций](investigations/claude-for-legal-capabilities.md) и
[характеристики VPS](investigations/legal-mcp-vps.md) уточняют объём и ресурсные предположения.

## Что уже реализовано

В репозитории остаются синтетический DOCX-конвейер, [рабочий AI-прототип UI](runbooks/live-ide.md)
и [эксперимент общего RAG](investigations/shared-legal-rag-spike.md). Готового MCP,
устанавливаемого юридического плагина и самостоятельной desktop IDE пока нет.
Дальнейшие разделы описывают исходное демо; его ограничения не определяют весь scope
новых модулей и сохраняются для нынешней реализации.

## Цель и scope исходного демо

Показать на одном вымышленном договоре оказания услуг, как отделить извлечение данных от
проверяемого текста и детерминированного заполнения DOCX. Пользователи демо — разработчики,
изучающие этот подход. Запуск локальный, через Python; веб-сервиса и пользовательского UI нет.

В scope входят интерфейс извлечения, mock и JSON-адаптер, YAML-схема полей, расчёты,
заполнение DOCX, проверки результата и тесты структуры шаблона.

## Non-goals исходного демо

- Юридическая консультация, реальная сделка или автоматическая актуализация правового текста.
- Telegram, база данных, пользователи, авторизация, история версий и аудит.
- Готовая интеграция с LLM-провайдером, production deployment и обработка реальных документов.
- Универсальный движок расчётов: текущий код знает список `services` и рублёвые суммы.

## Основные правила

Текст документа задаёт шаблон. Извлечение даёт значения полей; вычисляемые значения формирует код.
При недостающих обязательных полях новый документ не рендерится. Успех требует проверки
готового DOCX. В примерах, шаблоне и результате сохраняются синтетические данные и маркировка.

## Термины

| Термин | Значение |
| --- | --- |
| `FieldSpec` | Поле из YAML: имя, обязательность, источник, тип и поля элементов списка |
| `source: user` | Значение для извлечения из запроса |
| `source: computed` | Значение для вычисления кодом |
| `Extractor` | Граница получения структурированных значений |
| `TextCompletion` | Граница внешнего клиента, возвращающего текст ответа |
| Слот | Подстановка или управляющая конструкция Jinja/docxtpl в DOCX |
| Golden | Ожидаемая структура шаблона в JSON, а не побайтовый снимок DOCX |
