# Execution plans

План описывает изменение после исследования кода. Требования описываются отдельно в
[specs](../specs/). Для мелкой локальной правки отдельный документ не нужен.

1. Скопировать [TEMPLATE.md](TEMPLATE.md) в `active/<task>.md` и заполнить известными фактами.
2. Связать spec, план и [CURRENT_STATE.md](../CURRENT_STATE.md).
3. Обновлять этапы, неизвестное и результаты проверок по ходу работы.
4. После выполнения критериев переместить в `completed/`, исправить ссылки и состояние.

Если владелец заменил направление или отменил план до завершения, убрать его из
`active/` и зафиксировать причину и действующий план в CURRENT_STATE. Незакрытые пункты
не считать выполненной реализацией. Удаление устаревших материалов по запросу владельца
сопровождать проверкой входящих ссылок; не хранить дубликаты отменённых требований.

`.gitkeep` сохраняет пустой `active/` в Git и не обозначает активную задачу.
Завершённые планы — история конкретной работы; актуальные правила находятся в AGENTS и runbooks.
