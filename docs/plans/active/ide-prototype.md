# Проверочный прототип универсальной юридической IDE

Дата: 2026-10-19. Статус: отдельный первый цикл рабочего AI-прототипа выполнен;
полный план Windows/DOCX/RAG ниже остается открытым.
Требования: [vision](../../specs/legal-ide-vision.md), [RAG/навыки](../../specs/agent-knowledge-skills.md),
[псевдонимизация](../../specs/local-pseudonymization.md).

## Цель

На Windows пройти один полный цикл: задача клиента → защищенный контекст → найденный источник →
выполнение навыка → предложение правки DOCX → локальная обратная подстановка → review и undo.
Повторить его на другом деле и проверить вход без документов. IT/закупки — тестовые профили,
не жесткое ограничение архитектуры. Прототип не равен коммерчески готовому продукту.

## Исследованное состояние

Сейчас есть Python-пакет для одного DOCX-шаблона, pytest/Ruff и CI. Desktop, Node-приложения,
RAG, провайдеров LLM, псевдонимизации и agent runtime нет. Разработка ведется на macOS;
проверка Windows должна быть отдельным наблюдаемым этапом, не предположением.
Существующие незакоммиченные документы и синтетическое демо сохраняются.

## Подготовленные решения

- Пользователь выбрал совместимый endpoint `http://82.112.52.41:59425/chat/completions`
  и `o4-mini-2025-04-16`. Ключ на проверке не потребовался. API сообщил другое имя модели;
  см. [выполненный первый цикл](../completed/live-agent-prototype.md).
- Доступа/контактов КонсультантПлюс и ГАРАНТ нет; нужны условия обоих поставщиков.
- Редактор и его лицензия выбираются после испытаний. Коммерческая закупка не выполнена.
- Локальную часть можно начать с синтетических файлов и тестовых адаптеров; это не проверка
  качества реальной модели/правовой базы и не выполнение требования всей базы при релизе.
- Первый прототип навыков — схема процедуры, генерация черновика, тест и сохранение версии;
  не требуется маркетплейс или выполнение произвольного кода.

## Этапы с условиями перехода

- [ ] **1. Корпус и ожидаемые результаты.** Синтетический IT-договор, ТЗ/приложение и PDF;
  второй независимый пакет, запрос без файлов. Заложить разные стороны, скрытые сведения,
  таблицы, revisions, противоречия и неоднозначные имена. Отдельно обеспечить 30 DOCX/15 PDF
  для испытания совместимости редактора. Реальные материалы — только разрешенные, вне Git.
  Проверка: размеченные сущности, ожидаемые операции и критерии; фиксированные версии набора.

- [ ] **2. Локальный контекст и защита.** Модель дела, entity references, версии документа,
  псевдонимизация чата/файлов, безопасные результаты инструментов и обратная подстановка.
  Проверка: исходящий перехват без запрещенных значений, чужие токены заблокированы,
  ошибочный разбор не вызывает передачу; связи и роли восстановлены правильно.

- [ ] **3. Windows-оболочка и DOCX.** Папка, вкладка документа, панель задачи, журнал операций.
  Испытать основной DOCX-кандидат и сравнить с резервным; редактор должен принимать адресные
  операции и отдавать корректный Word-файл. Проверка: ручные/программные правки, сохранение,
  review/undo, конфликт внешнего изменения и запуск на Windows.

- [ ] **4. Реальный агент и RAG.** Подключить выбранный API через адаптер; искать по точному
  тексту и смыслу в разрешенном корпусе, возвращать точный фрагмент/редакцию/происхождение.
  Реализовать [контракт цитирования](../../specs/legal-citations.md): зарегистрированные доказательства,
  программная проверка цитат, отдельный статус применимости, переход к выделенному пункту.
  Добавить отдельного проверяющего с повторным получением источников, вердиктами по утверждениям
  и ограниченным циклом исправлений. Сравнить обнаружение ошибок с вариантом без проверяющего;
  техническая ошибка проверки не должна давать положительный статус.
  Проверка: одна задача с правильным источником, одна с устаревшим, одна без достаточных
  доказательств. Mock-проверки протокола не засчитывать за качество модели.

- [ ] **5. Конструктор навыков.** Из инструкции создать декларативную процедуру, запустить
  на копии, сохранить и применить ко второму делу. Проверка: результат соответствует схеме,
  лишние инструменты запрещены, версия зафиксирована, данные первого клиента не перенесены.

- [ ] **6. PDF и источники.** Проверить viewer/OCR; отдельно сравнить прямые программные
  PDF-правки с вариантом нового DOCX. На реальном API базы проверить поиск, фрагмент,
  редакцию, встроенное отображение и тарификацию после получения тестового доступа.
  Проверка: отчет о поддержке и потерях, карта покрытия базы и ограничения договора.

- [ ] **7. Сквозная приемка.** Пройти полный цикл на Windows с реальными адаптерами;
  проверить отсутствие раскрытия оригиналов, сохранность файла, цитаты, откат, повтор запроса
  и другой профиль. Записать стоимость задачи, задержки, ошибки и следующий объем разработки.

Локальные этапы не зависят от покупки правовой базы; этапы с реальными сервисами требуют доступа.
Полная продуктовая база обязательна до выпуска; технический корпус не заменяет это условие.

## Первый короткий цикл

Первые десять рабочих дней при доступных evaluation-лицензиях и двух инженерах посвятить
корпусу, защите данных и проверке редактора; остальные этапы дают план дальнейшей сборки.
Это ориентир испытаний, не обещание готовности всей IDE или всех семи этапов за две недели.
Приоритет первого изменения кода — корпус и локальный контракт защищенных операций.

## Предыдущий shortlist моделей

Предложения ниже сохранены как исследование до выбора пользователя. В рабочем прототипе
реализован указанный пользователем endpoint и точное имя o4-mini, сравнение провайдеров не проводилось.

Срез официальных условий на 2026-10-19. Для первого адаптера предлагается **Yandex AI Studio**;
выбор по доступности коммерческого подключения и документации, не доказанному превосходству.

| Кандидат | Публичные параметры | Роль в испытании |
| --- | --- | --- |
| YandexGPT Pro 5.1 | Контекст 32 768; синхронно 0,80 ₽/1000 входных и 0,80 ₽/1000 выходных токенов с НДС | Первый адаптер, адресные правки и инструменты |
| Alice AI LLM в AI Studio | Контекст 131 072; синхронно 0,50 ₽/1000 входных и 1,20 ₽/1000 выходных с НДС | Сравнение длинных документов на том же провайдере |
| GigaChat через Cloud.ru | Новые платящие клиенты GigaChat с 01.09.2026 направляются в Cloud.ru; старый прайс Салют не применять | Второй провайдер; проверить точную модель, инструменты, цену и условия данных перед подключением |

Источники: [модели Яндекса](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models),
[цены](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing),
[изменение подключения GigaChat](https://developers.sber.ru/docs/ru/gigachat/tariffs/legal-tariffs),
[каталог Cloud.ru](https://cloud.ru/products/evolution-foundation-models).
Это shortlist для доступного в РФ пилота, не исчерпывающий рейтинг моделей; адаптер собственного API остается требованием.

В AI Studio вызов инструментов и финальную выдачу операций по JSON Schema разделить:
[документация structured output](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/structured-output)
указывает несовместимость `tools` и structured output в одном запросе. Поддержку конкретной модели
проверить реальными запросами. Для отправки нужны `x-data-logging-enabled: false`, отключенный
трейсинг и при Responses — `store: false`. Не использовать облачные Conversations и загрузку
оригиналов. Отключение логирования и хранение агентских объектов — разные настройки:
[логирование](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging),
[хранение](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage).
Условия Cloud.ru проверить отдельно; не переносить заявления Сбера о данных на другого оператора.
Переключение провайдера требует разрешенного маршрута в настройках, не скрытого fallback.

Отбирать по tool calling, надежности структурированных операций, русскому тексту, условиям
обработки запросов, оплате/доступности и стоимости выполненной задачи. Провести одинаковые
20–30 заданий на двух моделях: источники, правки, неоднозначность, поврежденный token,
попытка обойти защиту и недостаток фактов. Сохранить входы/выходы только синтетического корпуса.
Выбор по документации дает кандидата, окончательный выбор — по измерениям.

## Доступ к законодательству

Дополнительно исследована [собственная база из открытых источников](../../investigations/open-legal-sources.md).
Это альтернатива коммерческому API, требующая проверки прав на выгрузку, полноты и обновлений.
Готовые скачиваемые корпуса не приняты как полноценная актуальная база.

Подготовлен [запрос условий](../../runbooks/legal-api-evaluation-request.md) для ГАРАНТ и
КонсультантПлюс/уполномоченного партнера. Публичные API подтверждают техническую возможность,
но пока не подтверждены OEM-права, покрытие, обработка моделью, SLA и общая цена.
Обращения не отправлены. Ответы поставщиков сохранять как доказательства условий,
не подменять их рекламой или индивидуальным тарифом для обычного подписчика.

## Результат spike и дальнейшие решения

Нужны работающая проверочная сборка, отчет корпуса, измерения двух моделей, выбор редактора
и PDF-объема, условия правовой базы, ADR и оценка следующего этапа. Блокеры записывать явно.
Не считать прототип готовым, если путь работает только с mock, не испытан на Windows или
скрывает потери DOCX/неопределенность источника.
