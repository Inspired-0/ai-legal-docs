# Исследование IDE для юристов

Дата: 2026-10-18. Статус: исследование завершено; решения по реализации открыты.

## Цель

Подготовить рыночный анализ, видение продукта и реализации, этапы разработки и вопросы
владельцу. Запрос: рабочее пространство по образцу Cursor, папки документов, Word/PDF,
агент с редактированием, собственный API модели, правовые источники и обоснования формулировок.
Реализация продукта в этой задаче не заказана.

## Контекст и границы

Текущий код — Python/DOCX демо; нет редактора, PDF, хранения дел, провайдеров LLM и поиска.
Существующие изменения документации в рабочем дереве сохраняются. Проектные ограничения
синтетического демо описывают текущую реализацию, но не ограничивают новое видение владельца.
РФ — рабочее предположение по упоминанию КонсультантПлюс.
Во время исследования владелец выбрал in-house договорную работу и desktop с локальными
папками; для PDF попросил сравнить оба варианта вместо окончательного выбора.

## Риски и проверки

Маркетинговые заявления не равны проверенному качеству. Нативность DOCX/PDF требует spike.
Доступ на чтение правовой базы не подтверждает право массового индексирования или API.
Смета и сроки зависят от команды, лицензий, форматов и редактора; давать условные оценки.
Проверка: ссылки на первичные источники, маркировка предположений, отсутствие утверждений
о несуществующих возможностях текущего проекта, валидность локальных ссылок и git diff --check.

## Результат и ревью

- [Рынок, технологии и источники](../../investigations/legal-ide-market.md): девять продуктов,
  движки Word/PDF, пути получения норм/практики, публичные условия и вопросы поставщикам.
- [Видение](../../specs/legal-ide-vision.md): выбранный сегмент, desktop-архитектура, агентные
  операции, RAG, варианты PDF, spike, критерии, этапы и вопросы владельцу.
- Read-only subagents исследовали рынок, движки и правовые источники; последние два отдельно
  проверили итоговые документы. Исправлены замечания о PDF→DOCX, приемке прямых PDF-правок,
  календаре/трудоемкости, стоимости пакета API и будущих редакциях норм.
- Проверены локальные Markdown-ссылки, парность code fences, пробелы и git diff --check.
  Исходники не менялись; pytest/Ruff повторно не запускались для документального исследования.
- Продукты и коммерческие API не тестировались; внешние обращения/покупки не выполнялись.

## Следующее решение

Уточнить типы договоров, ОС, допустимые API/контур данных, бюджет/команду, PDF-объем
и пилотный корпус. Затем создать отдельный план spike. Поставщики и scope пока не утверждены.
