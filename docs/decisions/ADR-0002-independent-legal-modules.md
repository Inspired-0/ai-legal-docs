# ADR-0002: самостоятельные правовой MCP и агентный плагин

Дата: 2026-10-30. Статус: принято по прямому решению владельца.
Технические рекомендации исследования, не перечисленные как решения ниже,
остаются предложениями.

## Контекст

Прежний продуктовый план объединял документы, RAG, агентные процедуры и защищённый
контекст в один Windows MVP. Владелец изменил порядок разработки и потребовал
самостоятельную ценность модулей до появления собственной IDE.

## Решение

1. Правовой MCP является отдельным общим сервером для ChatGPT и Claude. В нём находятся
   правовой корпус РФ, поиск/RAG, работа с редакциями и обновление на основе newsBot.
   Первый охват федеральный, широкий; ежедневное обновление и журнал входят в выпуск.
2. Плагин устанавливается в Codex и Claude Code. Он работает с материалами пользователя
   самостоятельно; подключение нашего MCP расширяет доступ к правовым источникам.
3. IDE разрабатывается третьим модулем и подключает первые два и другие интеграции.
4. Первый плагин работает в обычной среде файлов агента. Псевдонимизация переносится
   в отдельный будущий защищённый режим по уточнению владельца.
5. Весь каталог claude-for-legal входит в целевой объём плагина; создание и проверка
   договоров с DOCX идут первыми. Платные правовые источники исключены, включая CoCounsel.
   Собственный исследовательский агент отложен; обычные исследовательские процедуры сохраняются.
6. MCP размещается на VPS. Юридическую проверку выполнят юристы позже; техническая
   реализация и измерения не требуют их немедленного участия.

У модулей разные жизненные циклы, версии и критерии выпуска. Общий исходный репозиторий
допустим, пока сборка и запуск первых двух не требуют IDE и друг друга. Выбор структуры
репозиториев, SDK, БД, провайдера и размера VPS данным ADR не утверждается.

## Альтернативы и причины выбора

Единый Windows MVP отложил бы пользу правовой базы и процедур до готовности редактора,
упаковки и локальной защиты. Набор навыков с обязательным нашим MCP также не выполняет
требование самостоятельной ценности плагина. Выбранное разделение позволяет проверять
продуктовую пользу каждого модуля в существующих агентных клиентах.

## Последствия и ограничения

Нужны явные интеграционные контракты и отдельная проверка на каждом хосте. Плагин
не гарантирует скрытие переданных хосту файлов. MCP не контролирует рассуждение
произвольного подключённого агента и не может принудительно обеспечить его независимое
ревью; он обеспечивает свой контракт источников и проверок.

Прежние IDE-spec и планы удалены 31.10.2026 по запросу владельца. Их незавершённые
задачи не объявляются выполненными; оценки общего Windows MVP не используются для новых выпусков.
