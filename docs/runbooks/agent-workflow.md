# Работа с задачами и контекстом

## Постановка задачи

Используй формат: **Goal → Context → Constraints → Done when → Verification**.
Укажи наблюдаемый результат, нужные файлы, сохраняемые контракты и способ проверки.
Не диктуй структуру реализации до исследования существующего кода.

Пример: «Добавить проверку некорректного количества услуги. Контекст: templates/fields.py,
тесты расчётов, spec демо. Сохранить корректные расчёты и синтетический сценарий.
Сначала определить ожидаемый результат для некорректных значений, затем добавить проверку
и регрессионный тест; запустить pytest и Ruff». Это пример постановки, не активная задача.

## Spec, план и ревью

- Spec отвечает «что должно работать»: [шаблон](../specs/TEMPLATE.md).
- План отвечает «как изменить текущую систему»: [шаблон](../plans/TEMPLATE.md).
- ADR объясняет долговечное решение и альтернативы: [шаблон](../decisions/TEMPLATE.md).

Масштаб процесса выбирается по AGENTS.md. Читай конкретный execution path и тесты до плана.
После этапа запиши проверку; при новых фактах пересмотри план.
Ревью важных изменений должно проверять diff, критерии, интерфейсы, инварианты и тесты
в свежем контексте. При недоступном независимом ревью обозначь это явно.

Read-only исследование можно делегировать при разрешённой работе с subagents; возвращать
пути, выводы и неизвестное, а не сырые логи. Параллельные изменения выполняются в отдельных
worktrees/ветках. Модель и её параметры выбираются по доступности и сложности задачи,
без закрепления временных названий и тарифов в репозитории.

## Handoff и compaction

Перед завершением длинной сессии или передачей обнови CURRENT_STATE:

```text
Дата и задача
Что сделано (ссылки на spec/plan/ADR)
Что осталось или блокирует работу
Проверки: команда → результат; что не запускалось
Следующий конкретный шаг
```

Обнови активный план и вынеси долговечные решения в ADR. Завершённые планы перенеси
в completed и исправь ссылки. В новой сессии достаточно AGENTS → INDEX → CURRENT_STATE →
релевантный spec/plan; предыдущий чат не должен быть необходим.
Не копируй весь журнал команд в CURRENT_STATE и не создавай пустые «активные задачи».
