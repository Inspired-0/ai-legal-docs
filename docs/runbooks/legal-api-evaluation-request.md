# Запрос условий API правовой базы для юридической IDE

Дата: 2026-10-19. Статус: готовый проект обращения; не отправлен.
Адресаты: ГАРАНТ Коннект; КонсультантПлюс или уполномоченный партнер по API.

## Текст обращения

Здравствуйте!

Мы проектируем коммерческое приложение для Windows: рабочее пространство юриста с редактором
документов и AI-агентом. Нужен встроенный доступ к законодательству РФ, редакциям и судебной
практике. Первые проверочные сценарии — IT-договоры и участие поставщика в закупках по 44-ФЗ/223-ФЗ.
Планируется несколько независимых компаний-клиентов. Объем пользователей и запросов оцениваем;
просим предложить условия для пилота и масштабирования, указав необходимые исходные параметры.

Просим предоставить техническую документацию, тестовый доступ и коммерческое предложение:

1. Разрешена ли интеграция в тиражируемое коммерческое desktop-приложение? Требуется ли отдельная
   подписка/токен каждому конечному пользователю или организации, возможен ли OEM-договор?
2. Каково покрытие федеральных, региональных и муниципальных актов, исторических и будущих
   редакций? Какие судебные материалы, комментарии и готовые формы включаются отдельно?
3. Можно ли искать и показывать полный текст/фрагмент во встроенной вкладке нашего приложения?
4. Допускаются ли передача полученных фрагментов выбранной клиентом LLM для генерации ответа,
   RAG, embeddings и цитирование? Есть ли ограничения по провайдерам и месту обработки?
5. Разрешен ли локальный/серверный кеш, на какой срок? Что необходимо удалить после окончания
   подписки, и можно ли сохранить доказательства цитирования в уже выполненной работе клиента?
6. Есть ли стабильные идентификаторы актов/пунктов, интервалы действия редакций, признаки
   будущих изменений и статусы последующего пересмотра судебных актов?
7. Какие операции оплачиваются отдельно: поиск, получение фрагмента, полный текст, редакции,
   проверка актуальности? Укажите квоты, ограничения, стоимость превышения и минимальный платеж.
8. Каковы сроки обновления, SLA, доступность сервиса и порядок уведомления об изменениях API?
9. Как хранятся и используются поисковые запросы? Передаваемые клиентские сведения будут
   псевдонимизированы; допускается ли исключить их обучение/повторное использование?
10. Можно ли выдать тестовый комплект с законодательством и практикой для проверки 20–30
    сценариев и провести техническую консультацию по архитектуре доступа?

Просим отдельно обозначить условия, требующие письменного согласования сверх стандартного API-доступа.
