# Технический аудит pravo.gov.ru

Дата: 2026-10-19. Продолжение [исследования открытых источников](open-legal-sources.md).
Цель: собственная обновляемая база для коммерческой юридической IDE.

## Результат и уровень доказательств

Получение большого корпуса технически возможно: живыми HTTP-ответами подтверждены официальный
API публикаций, пагинация, фильтр даты, карточка, PDF, каталог ИПС, список редакций и экспорт текста.
Предыдущее «API не подтвержден» уточняется: интерфейс официального опубликования документирован
и работает. Полный охват всех актов/редакций, устойчивость загрузки и коммерческое копирование
всего банка по-прежнему не подтверждены. Массовая загрузка не выполнялась.

Проверки проводились обычными публичными HTTP-запросами из shell, без авторизации и обхода
ограничений. HTTPS и web-инструмент часто завершались таймаутами; это не отсутствие данных.
Ответы сохранены временно, в Git не импортированы тексты актов. Работоспособность HTTP нельзя
выдавать за проверенный защищенный транспорт: для эксплуатации отдельно проверить HTTPS,
подписи/происхождение, целостность и режим доступа. Хеш фиксирует полученную копию, не ее подлинность.

Сохранен [журнал наблюдений](pravo-audit-manifest.json): 23 соответствия URL/временный файл,
HTTP-статусы, размеры, SHA-256 и счетчики. Несохраненные ответы отмечены отдельно.
Полнота сохраненного HTTP-ответа не означает полноту содержащегося в нем правового текста.

Дополнение после чтения соседнего newsBot: отдельно проверен ЕБПИ на порту 8000,
получены история редакций ГК I, HTML до статьи 453 и связь по номеру опубликования.
См. [исследование и границы проверки](newsbot-sources.md#живая-проверка-ебпи)
и [три новых наблюдения](newsbot-ebpi-probe.json); исходный журнал из 23 наблюдений не изменен.

## Ресурсы портала

| Ресурс | Назначение | Использование в нашей базе |
| --- | --- | --- |
| publication.pravo.gov.ru | Официальные публикации, карточки, оригинальные PDF | Поток новых актов и доказательство публикации |
| pravo.gov.ru/proxy/ips | ИПС «Законодательство России», тексты и редакции | Структурируемый текст и история изменений |
| actual.pravo.gov.ru:8000/api/ebpi | ЕБПИ: JSON метаданных редакций и HTML текста | Дополнительный канал получения редакций и связи с номером опубликования |
| publication.pravo.gov.ru/OpenData | Четыре открытых набора с условиями повторного использования | Статистика/справочники; не архив полных текстов |

Размещение в банке ИПС не равно событию официального опубликования. При этом тексты определенных
категорий в банке имеют официальный статус: нельзя автоматически объявлять весь банк
«неофициальным» на основании старых описаний сторонних сборщиков.
[Официальный портал](http://pravo.gov.ru/).

Охват портала включает федеральные и региональные акты, отдельные другие категории.
Возможность размещения муниципальных актов не гарантирует полноту муниципального массива;
всю судебную практику портал также не обещает. [О портале](http://pravo.gov.ru/o-portale.php).

## Проверенные запросы публикаций

Официальная [справка API](http://publication.pravo.gov.ru/help) получена с HTTP 200:
135 818 байт. Описан интерфейс только чтения для приложений/веб-сервисов, карточки, поиск,
справочники и размеры страницы 10/30/100/200. Справочники перечислены в документации,
но каждый отдельно не проверялся. Наличие API не является обещанием SLA или прав на весь ИПС.

| Запрос на host publication.pravo.gov.ru | Наблюдение |
| --- | --- |
| `/api/Documents?PageSize=10&index=1` | JSON: items, itemsTotalCount, itemsPerPage, currentPage, pagesTotalCount |
| `/api/Documents?PageSize=10&index=2` | Еще 10 записей, без пересечения с первой страницей |
| `/api/Document?eoNumber=0001202610190008` | Карточка: реквизиты, орган, GUID, дата публикации, размер/страницы PDF |
| `/File/Pdf?eoNumber=0001202610190007` | Настоящий PDF, 89 163 байта; каталог указывает две страницы |
| `/api/Documents?pageSize=10&index=1&EoNumber=0001202610190007` | Ровно одна запись |

Ссылки для воспроизведения: [первая страница](http://publication.pravo.gov.ru/api/Documents?PageSize=10&index=1),
[вторая](http://publication.pravo.gov.ru/api/Documents?PageSize=10&index=2),
[карточка](http://publication.pravo.gov.ru/api/Document?eoNumber=0001202610190008),
[PDF](http://publication.pravo.gov.ru/File/Pdf?eoNumber=0001202610190007).

Во время проверки счетчик — **1 714 234 публикации**, не действующих законов. Если размер
страницы 200 работает для всего массива, инвентаризация потребует около 8572 запросов;
файлы и редакции загружаются отдельно. Это расчет по счетчику, не выполненная полная выгрузка.
Пагинация при пополнении массива может смещаться; нужны фиксированные интервалы и дедупликация.

### Обновление по дате

Рабочая проверенная комбинация:

```text
http://publication.pravo.gov.ru/api/Documents?pageSize=10&index=1&PublishDateSearchType=0&PublishDateFrom=29.02.2024&PublishDateTo=29.02.2024
```

[Запрос](http://publication.pravo.gov.ru/api/Documents?pageSize=10&index=1&PublishDateSearchType=0&PublishDateFrom=29.02.2024&PublishDateTo=29.02.2024)
вернул 699 записей по счетчику; все 10 полученных имеют дату 2024-02-29. Роль параметра
SearchType и формата даты по отдельности еще не изолирована.
В пробах `PeriodType=day&Date=2024-02-29` и ISO-диапазон без дополнительных параметров
возвращали весь каталог. Нельзя считать отсутствие HTTP-ошибки доказательством работы фильтра.
Загрузчик должен проверять даты ответа, повторять перекрывающееся окно и устранять дубли.

## ИПС: тексты и редакции

[Каталог кодексов](http://pravo.gov.ru/proxy/ips/?list_itself=&bpas=cd00000&a3=102000486&lstsize=20&start=0)
вернул HTML Windows-1251. `start=20` дал записи начиная с 21-й. Каталог включает утратившие
силу акты; попадание в выдачу не означает применимость сегодня. Полный обход всех категорий не выполнен.

На [карточке ГК РФ, части первой](http://pravo.gov.ru/proxy/ips/?docbody=&nd=102033239)
обнаружен список исходной редакции и `rdk=1…157`, а также состояние «не готова».
Последняя выбранная редакция обозначена изменением от 04.08.2026 №282-ФЗ.
`rdk` — идентификатор версии источника, не дата вступления всех положений в силу.

| Запрос на pravo.gov.ru/proxy/ips/ | Результат |
| --- | --- |
| `?doc_itself=&nd=102033239&page=1&rdk=0` | HTML исходной редакции: 439 186 байт |
| `?doc_itself=&nd=102033239&page=1&rdk=157` | Другой HTML: 588 260 байт, заканчивается внутри статьи 183 |
| `?doc_itself=&nd=102033239&page=2&rdk=157` и `page=all` | В проверке возвращали тот же неполный текст |
| `?savertf=&nd=102033239&page=all&rdk=157` | 913 142 байта, текст до статьи 453 и заключительных реквизитов |

[Экспорт](http://pravo.gov.ru/proxy/ips/?savertf=&nd=102033239&page=all&rdk=157)
имеет имя с `.rtf`, но фактически содержит MIME multipart/related с HTML.
Определять формат нужно по содержимому. Наличие последней статьи — полезная проверка,
но еще не полное доказательство побуквенной точности и наличия всех приложений.

Вывод: перечислять версии из карточки, получать проверенный экспорт, извлекать текст
с сохранением разметки, сверять начало/конец/структуру/приложения. Не использовать `page=all`
как безусловную гарантию полноты и не считать `rdk=0` текущей редакцией.

## OpenData и коммерческое использование

На [странице условий](http://publication.pravo.gov.ru/OpenData) разрешены бесплатное
повторное использование, копирование, распространение, изменение и коммерческое применение
опубликованных открытых данных при соблюдении условий, включая ссылку и неискажение.
Это разрешение именно для открытых наборов, не автоматически для всей ИПС.

[Реестр JSON](http://publication.pravo.gov.ru/OpenData/list.json) содержит четыре набора:
30/90/360 дней и органы. [Паспорт](http://publication.pravo.gov.ru/opendata/7710349494-legalacts-30/meta.json)
указывает источник, обновление и ссылки на CSV/схему.
[Схема](http://publication.pravo.gov.ru/opendata/7710349494-legalacts-30/structure-legalacts.csv)
и первые 4096 байт CSV подтверждают агрегаты по органам: ID, название, начало/конец периода,
число публикаций и URL списка. Это не построчные карточки актов и не тексты.

Правовой режим самих официальных текстов, готовой базы, авторских материалов и массового
доступа необходимо различать; см. [предыдущее исследование](open-legal-sources.md#права-на-тексты-и-базу).
До коммерческого распространения выяснить условия полного банка, кеширования и обновлений.
Не требуется трактовать эту неопределенность как запрет на техническое исследование.

## Нормативно описанные редакции и обмен

[Указ Президента №90 от 03.03.2022](https://www.systema.ru/upload/iblock/3cb/cvrsnfxnd29c89fdss441v8j9vyin3ai/ukaz90.pdf)
задает официальный статус соответствующих текстов с изменениями с 01.07.2022. Это основание
статуса текста, не лицензия на массовую выгрузку.

[Приказ ФСО №121 от 02.09.2024](https://www.consultant.ru/document/cons_doc_LAW_489896/2de3d28bac247224615146d221dffeffd645a69f/)
различает актуальные, будущие и ранее действовавшие редакции. Предусмотрены сроки подготовки
актуального текста: до 15 рабочих дней для законов и 7 для актов Президента. Поэтому нельзя
обещать готовую консолидацию сразу после публикации поправки. Нужен статус ожидания и проверка
поправок/дат действия до выдачи уверенного ответа агентом.

[Приказ ФСО №92 от 04.07.2024](https://www.consultant.ru/document/cons_doc_LAW_490903/56d791477c7461261b3adcc9631a9cfd9d0852bb/)
описывает пакет `.up4`: 7-Zip, XML метаданных, HTML редакций, приложения/образы и сведения
о статусах, изменениях, контрольных суммах и подписях. Это формат обмена/представления,
не доказательство общедоступной выгрузки. Раздел НТЦ «Система»
[«Порции пополнений»](https://www.systema.ru/informational_resources/refill/) требует авторизации.
Условия такого канала стоит выяснить отдельно; доступ не запрашивался.

## Почему не берем готовый сборщик без аудита

Исходник [collect_pravo.py](https://huggingface.co/datasets/endomorphosis/ipfs_russia_laws/raw/main/scrapers/collect_pravo.py)
прочитан, но не запускался. Он фиксирует `rdk=0`, не обходит все версии; неизвестный статус
может преобразовывать в `current=True`, а при сбоях брать архивную копию. Совмещение старого
текста с меткой текущего каталога нельзя использовать как подтверждение актуальности.
Ранее найденный снимок остается техническим кандидатом, не принятой продуктовой базой.

## Следующая проверочная реализация

1. Адаптер публикаций: инвентаризация ограниченного интервала, проверенные фильтры, пагинация,
   дедупликация по номеру публикации; ограниченная частота, повтор с задержкой и журнал ошибок.
2. Адаптер ИПС: 10–20 контрольных актов разных размеров/типов, действующая и историческая
   версии, незавершенная редакция, приложения. Экспорт и контроль полноты, без массового обхода.
   Добавить ЕБПИ из исследования newsBot: сравнить покрытие/историю и проверить выбор редакции
   на дату; `actual`, `redofficial`, готовность текста и период действия — разные признаки.
3. Нормализация в реестр акт → редакция → структурная единица; внешние `nd`, `rdk`, `eoNumber`
   хранятся как соответствия. Связи между системами проверяются по реквизитам и содержанию.
4. Даты публикации, вступления, редакции и получения — разные поля. Неизвестные интервалы
   действия и запаздывающая консолидация блокируют отметку «применимость проверена».
5. Повторный запуск должен находить только изменения, сохранять старые версии и помечать
   затронутые выводы IDE. Проверка сети/фильтров/формата при сбое не заменяется догадкой LLM.

Критерий успеха первого адаптера — воспроизводимо полные контрольные тексты с правильными
редакциями и обновлением. Миллионы файлов без этих свойств не выполняют требования продукта.
Фактическая разработка адаптера в этой задаче не выполнялась: созданы исследование и UI-макет.
