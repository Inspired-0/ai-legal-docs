# Конкуренты и движки документов для юридической IDE

Исследование: 2026-10-18. Отбор материалов для модульной концепции: 2026-10-31.
Здесь сохранены сравнение продуктов и варианты Word/PDF для будущего модуля
[IDE](../specs/legal-ide-shell.md). Текущий порядок работы задаёт
[дорожная карта](../plans/active/modular-platform-roadmap.md).

Возможности описаны по материалам поставщиков, без собственного тестирования.
Поддержка DOCX/PDF, лицензии, доступность и цены проверяются заново при выборе движка.
Исследование не определяет срок и состав выпуска модулей. Правовые источники
выбираются по [исследованию MCP](modular-legal-platform.md); платные данные исключены.

| --- | --- | --- |
| Harvey | Vault хранит документы/знания; агенты запускаются в Word с контекстом из Vault и дают правки с review/tracked changes. Knowledge подключает внешние правовые источники. [Vault](https://www.harvey.ai/platform/vault), [Word](https://www.harvey.ai/blog/run-custom-harvey-agents-in-microsoft-word), [Knowledge](https://www.harvey.ai/platform/knowledge) | Агент, работающий с контекстом и правками, уже стал продуктовым сценарием. |

[Editor](https://legora.com/product/editor), [Word](https://legora.com/product/word-add-in) | Прямой референс самостоятельной среды; экспорт Word не равен доказанной сохранности любого входного DOCX. |

[AI-продукты](https://www.lexisnexis.com/en-us/solutions/ai.page), [drafting](https://www.lexisnexis.com/en-us/products/lexis-plus-protege/legal-drafting.page) | Обоснования должны проверяться в контексте правовой базы, а не только существования URL. |

[Описание](https://www.consultant.ru/about/nc/demoiip/) | Прямой российский конкурент в проверке договора; встроенный редактор этим источником не подтвержден. |
| ГАРАНТ ИСКРА | Ответы по праву РФ и ссылки; для 2.0 заявлены загрузка файлов, проверка и редактирование текста. На странице одновременно предлагается заявка на ранний доступ. [ИСКРА](https://iskra.garant.ru/) | Нужны демо и проверка доступности 2.0; не считать обещанные функции проверенным DOCX/PDF-редактором. |

Числовых сопоставимых тарифов большинства перечисленных платформ на просмотренных страницах
нет. Spellbook публикует индивидуальное ценообразование по пользователям и 7-дневный trial,
а не единую ставку. Не стоит строить наше ценообразование на неофициальных обзорах цен.
[Spellbook pricing](https://spellbook.com/pricing).

Международные отчеты дают сигнал интереса, но не размер доступного нам рынка РФ. Например,
исследование Thomson Reuters 2026 основано на 736 ответах представителей юрфирм из 46 стран
(421 из США), с дополнительными данными 203 респондентов корпоративных юридических служб.
Эта выборка не подтверждает российскую готовность платить.
[Методология отчета](https://www.thomsonreuters.com/en/institute/future-of-professionals-2026/report-legal).

## Движок Word

| Вариант | Документированные возможности | Ограничение для выбора |
| --- | --- | --- |
| SuperDoc | OOXML-модель, встроенный редактор без обязательного сервера поставщика; Document API для текста, таблиц и review. [Editor](https://docs.superdoc.dev/editor/), [API](https://docs.superdoc.dev/document-api/reference/) | Первый кандидат для desktop. Проверить реальные файлы и конкретную версию runtime. |
| ONLYOFFICE Docs Developer | Полноценный офисный редактор; Automation API связывает внешний интерфейс с документом и review. [API](https://api.onlyoffice.com/docs/docs-api/usage-api/automation-api) | Сильный сравнительный кандидат, но серверный компонент усложняет локальное приложение. Automation API оплачивается отдельно и доступен в Developer. |
| Word + Office.js | Tracking, список revisions, accept/reject; отдельные операции сравнения доступны в desktop Word. [Microsoft](https://learn.microsoft.com/en-us/office/dev/add-ins/word/manage-tracked-changes) | Альтернативный продукт внутри Word; не выполняет пожелание отдельной IDE без дополнительной оболочки. |
| Collabora Online | Офисный редактор, WOPI/PostMessage и Extract/Transform. [SDK](https://sdk.collaboraonline.com/25.04/CO-SDK-manual.pdf) | Резерв при корпоративном сервере. Возможность точечных правок в живой сессии требует дополнительной проверки API. |
| Tiptap Conversion | DOCX ↔ редактор; импорт tracked changes имеет перечисленные ограничения. [Матрица](https://tiptap.dev/docs/conversion/getting-started/feature-support-matrix), [revisions](https://tiptap.dev/docs/conversion/import/docx/tracked-changes) | При импорте теряется часть истории форматирования/перемещений/сносок. Не основной выбор для свободного обмена юридическими redline. |

Лицензии SuperDoc Editor и DOCX Engine различаются; право поставки выбранного runtime
нужно проверить отдельно от наличия открытого исходного кода редактора.
[Лицензия Engine](https://docs.superdoc.dev/resources/docx-engine-license/).

У ONLYOFFICE лицензия Development Server не предназначена для обслуживания конечных
пользователей; production и Automation API нужно оценивать отдельным предложением.
[Developer FAQ](https://helpcenter.onlyoffice.com/docs/faq/developer.aspx).
Бесплатная редакция сама по себе не доказывает пригодность условий для закрытого коммерческого продукта.

Полезная проверка документации SuperDoc: browser export и Document API export имеют разные
контракты и ограничения. Не переносить свойства одного runtime на другой.
[Browser export](https://docs.superdoc.dev/editor/export-options/),
[Document API export](https://docs.superdoc.dev/document-api/reference/export/to-docx/).

## Два уровня PDF

| | Просмотр, OCR, разметка и переработка в Word | Прямое редактирование PDF |
| --- | --- | --- |
| Результат | Оригинальный PDF, аннотации; при переработке новый DOCX из извлеченного текста с новой версткой | Новая версия PDF с изменением существующего содержимого |
| Компоненты | PDF.js для просмотра; отдельные OCR, поиск, аннотации/экспорт | Коммерческий SDK с content editing; OCR и конвертация могут лицензироваться отдельно |
| Преимущество | Меньше зависимость от платного SDK; соответствует чтению приложений/сканов | Точечные правки PDF без обязательного промежуточного Word |
| Ограничение | Не выполняет требование прямой правки исходного текста PDF | Шрифты, reflow, сканы, формы и программные операции требуют отдельных испытаний |
| Затраты | Интеграция viewer/OCR и собственный workflow; без платного viewer не значит без затрат | Те же базовые задачи плюс лицензия и тестирование слоя изменения контента |

PDF.js — просмотрщик/библиотека, не универсальный редактор исходного текста PDF.
[PDF.js](https://mozilla.github.io/pdf.js/getting_started/).
Docling можно испытать для структурного извлечения и OCR, но он не заменяет редактор.
[Docling](https://docling.ai/).
PDF→DOCX с попыткой сохранения исходной верстки — отдельная задача конвертера, испытаний
и возможной лицензии; она не включена автоматически в базовый вариант A.

Apryse документирует изменения текста/изображений и программный ContentEdit API; Nutrient
тоже предлагает content editing, но программный сценарий зависит от Content Editor license
и Document Engine. Для desktop нужно проверить именно локальный программный путь, а не только UI.
[Apryse ContentEdit](https://sdk.apryse.com/api/web/Core.ContentEdit.html),
[Nutrient API](https://www.nutrient.io/guides/web/editor/content-editor-api/).

Apryse и Nutrient предлагают подбор лицензии под использование; сопоставимая фиксированная
цена полного пакета desktop + content editing + OCR из просмотренных страниц не установлена.
Запрос должен включать Electron/OEM-поставку, offline, платформы, количество пользователей,
программные операции агента и сроки действия лицензии.
[Apryse pricing](https://apryse.com/pricing), [Nutrient pricing](https://www.nutrient.io/sdk/pricing/).

OCR не восстанавливает исходную структуру Word; для скана нужно явно отличать распознанный
текст от изображения. Подписанный/полученный документ сохранять неизменным оригиналом,
а любые правки — новой версией; обещание сохранения подписи после произвольных правок не давать.

## Проверка при выборе движка

Проверить документы с таблицами, нумерацией, сносками, комментариями и tracked changes,
сохранение и повторное открытие в Word. Для PDF отдельно измерить извлечение, OCR,
аннотации и прямую правку, если она войдёт в требования IDE. Наличие SDK не означает,
что агент умеет надёжно применять программные правки.

Запрос условий редактора должен охватывать локальную/серверную поставку, платформы,
программные операции, обновления и цену нужных компонентов. Договоры и SDK в рамках
этого исследования не приобретались.
