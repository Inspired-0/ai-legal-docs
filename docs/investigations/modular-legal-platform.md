# Реализация правового MCP, плагина и IDE

Дата исследования: 2026-10-30. Основание: [концепция](../specs/modular-legal-platform.md).
Исследованы публичные первичные документы платформ, исходники claude-for-legal,
локальный newsBot и текущий репозиторий. Подключение нового MCP в реальных клиентах
и установка нового плагина пока не проверялись.

## Предлагаемая техническая основа

Для первого модуля подходит отдельный Python-сервис с MCP через HTTPS, PostgreSQL
и самостоятельным процессом обновления корпуса. Поиск сочетает точное разрешение
реквизитов, полнотекстовую и векторную выдачи. Снимки источников, редакции и результат
разметки хранятся раздельно. Плагин содержит переносимые процедуры и локальные
инструменты документов; MCP подключается как дополнительный источник.

Это рекомендация исследования. Выбор поискового ранжирования, модели embeddings,
размера VPS и схемы доступа требует испытаний. Предыдущий эксперимент не измерял
нагрузку широкой федеральной базы.

После третьего раунда интервью уточнены ограничения: только бесплатные правовые
источники, развёртывание на VPS, юридическая проверка позже. Плагин охватывает весь
набор claude-for-legal с договорами/DOCX первым этапом; собственный исследователь
отложен. Дополнения: [каталог функций](claude-for-legal-capabilities.md),
[расчёт VPS и каналы данных](legal-mcp-vps.md).

## Подключение MCP

| Клиент | Подтверждено документацией | Что проверить на нашем сервере |
| --- | --- | --- |
| ChatGPT | Пользовательский удалённый MCP, streaming HTTP/SSE, настройка авторизации | Доступ в выбранном аккаунте, вход, обнаружение инструментов, поиск и переход к точной норме |
| Claude | Custom connector подключается к удалённому MCP из инфраструктуры Anthropic | Доступность HTTPS снаружи, вход, схемы результатов и работа с большими актами |
| Codex | Подключение удалённого MCP по URL | Наш набор инструментов и совместимость с плагином |
| Claude Code | Удалённый HTTP и локальный stdio, установка через `claude mcp` | Вход, отзыв доступа, ошибки и необязательность соединения для плагина |

Основания: [ChatGPT custom MCP](https://developers.openai.com/api/docs/guides/custom-mcp-server),
[Claude custom connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp),
[Codex: пример подключения](https://developers.openai.com/resources/docs-mcp),
[Claude Code MCP](https://code.claude.com/docs/en/mcp).
Поддержка протокола не подтверждает наличие нужных разрешений в аккаунте владельца.

Базовый транспорт предлагаем сделать Streamable HTTP на `/mcp`. Обычные вызовы поиска
должны завершаться запросом/ответом; первоначальная загрузка базы работает отдельным
заданием. Для результата нужны JSON-схема и читаемый текст с источниками.
[`structuredContent`](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#structured-content)
позволяет передавать структурированные данные; текстовый блок сохраняет совместимость.
Все основные сценарии доступны через tools. Resources и prompts можно добавить позже,
не делая их поддержку условием работы клиента.

Для закрытого пилота и персональных квот предлагаем OAuth. MCP проверяет токен,
область доступа и адресата; вход и выдачу токенов обслуживает отдельный провайдер
авторизации. Статический API-ключ не считаем универсальной заменой входу в ChatGPT
и Claude. Конкретный провайдер, способ регистрации клиентов и публичный бесплатный
доступ пока не выбраны. Основания: [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization),
[Python SDK: resource server](https://py.sdk.modelcontextprotocol.io/run/authorization/).

MCP сам по себе не запускает ежедневное обновление и не доставляет уведомления в
закрытый чат. Планировщик и журнал изменений живут на сервере; агент читает журнал
по запросу. Персональные рассылки потребуют отдельной функции доставки.

## Варианты серверной реализации

| Вариант | Причина выбрать | Цена решения |
| --- | --- | --- |
| Python и официальный MCP SDK | newsBot, парсер, RAG-проба и DOCX уже на Python; меньше границ между конвейером и сервером | Потребуется отдельно настроить web-развёртывание, авторизацию и лимиты |
| TypeScript MCP и Python workers | Подходит команде с TypeScript и при ранней разработке интерактивных MCP Apps | Два runtime, отдельный контракт между поиском и MCP |
| Управляемый MCP-хостинг поверх нашего backend | Рассматривался как способ упростить вход и эксплуатацию | Владелец выбрал VPS; этот вариант не входит в текущий план |

Рекомендация: начать с Python, поскольку серверные наработки уже на нём. Официальные
[Python SDK](https://py.sdk.modelcontextprotocol.io/) и
[TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server) поддерживают удалённый MCP.
Версию SDK фиксировать при реализации, после проверки примеров и совместимости клиентов.
MCP Apps для первого выпуска поиска не требуются.

## Корпус и поиск

Владелец выбрал широкий федеральный охват: кодексы, законы, постановления и ведомственные
акты. Загрузка нескольких выбранных кодексов остаётся техническим испытанием и не
выполняет это продуктовое требование.

| Бесплатный канал корпуса | Возможности | Неизвестное |
| --- | --- | --- |
| Собственный сбор официальных источников | Контроль снимков, истории обработки и обновлений; используются адаптеры newsBot | Полнота первоначальной загрузки, доступность старых редакций, условия массового сбора, качество OCR |
| Другие официальные каналы: Минюст, сайты органов, ИПС | Проверка каталога, дополнение пропусков и приложений | Автоматизация доступа, сопоставление ID, устойчивость и история |
| Открытый скачиваемый корпус с проверенным происхождением | Возможный способ ускорить первоначальную загрузку | Полнота, лицензия, актуальность и сверка каждого текста; подходящий корпус пока не выбран |

Используется собственный конвейер с заменяемыми адаптерами бесплатных источников.
Платный поставщик и смешанный платный вариант исключены прямым решением владельца;
ими нельзя закрывать обнаруженные пробелы. Основания: [аудит портала](pravo-portal-audit.md),
[открытые корпуса](open-legal-sources.md), [исследование newsBot](newsbot-sources.md),
[живая RAG-проба](shared-legal-rag-spike.md). Эти исследования не подтверждают полноту
всего федерального законодательства и не заменяют условия использования источника.

Нужны отдельные показатели: акт обнаружен в каталоге; оригинал получен; текст извлечён
полностью; доступна конкретная редакция; известны даты действия. Процент покрытия
имеет смысл только относительно определённого реестра и периода. Поиск по метаданным
должен находить и акты с отсутствующим текстом, явно сообщая, что содержание ещё недоступно.

| Поисковый стек | Преимущества для этой задачи | Когда пересматривать |
| --- | --- | --- |
| PostgreSQL FTS + pgvector | Реквизиты, версии и оба вида поиска в одной БД; есть собственный рабочий эксперимент | После измерений качества русскоязычного поиска и нагрузки широкого корпуса |
| PostgreSQL + OpenSearch | Отдельный поисковый сервис с лексическим и семантическим поиском и настройкой объединения | Если измерения покажут пользу, оправдывающую синхронизацию двух хранилищ |
| Поиск бесплатного официального API | Возможный дополнительный канал, если источник предоставляет нужные операции | Не подтверждён как замена нашему семантическому поиску; проверить даты, полноту и происхождение |

Оба собственных варианта поддерживают гибридный поиск:
[pgvector](https://github.com/pgvector/pgvector#hybrid-search),
[OpenSearch](https://docs.opensearch.org/latest/vector-search/ai-search/hybrid-search/index/).
Встроенное ранжирование PostgreSQL FTS не следует называть BM25.
Смена БД сама по себе не устраняет ошибки разметки или выбора редакции.

В нашем прогоне на 12 вопросах текстовый поиск дал 6/12 попаданий в первую пятёрку,
семантический 10/12, RRF 9/12. Поэтому предлагаем сохранить оба канала и сравнить способы
объединения, reranker и точный поиск на расширенной технической выборке, затем на
отдельной разметке юриста. По решению владельца юристы подключаются позже. Модель
`multilingual-e5-small` остаётся исходным измерением. Финальный выбор модели и весов
не сделан. Точный запрос по статье должен обходить ненужное семантическое ранжирование.

## Перенос системы обновлений из newsBot

Повторно прочитана рабочая копия `/Users/vladimir/Projects/newsBot` 30.10.2026;
HEAD `c65a4ea56f7357de17ee95149dc4dbcce746cf6b`. Код и тесты изучены без запуска сервиса,
его базы, рассылок или платных API. Владелец уточнил, что имел в виду newsBot;
AccountAnalysis не является источником реализации этого модуля.

| Механизм | Где найден | Как использовать |
| --- | --- | --- |
| Публикации, пагинация, проверка дат | `newsbot/sources/pravo_gov.py`, `tests/test_pravo_gov.py` | Обнаружение актов и контроль неполного ответа источника |
| Метаданные и текст редакций | `newsbot/sources/ebpi.py` | Адаптер получения редакции с сохранением ответа источника |
| Проверка новых редакций | `newsbot/watch/redactions.py`, `acts_registry.yaml` | Основа наблюдения за реестром актов |
| Повторная проверка прошлых дней | `newsbot/recheck.py`, `pipeline.py` | Добор поздних публикаций, сверка ожидаемых ключей с загруженными |
| Исключение конкурирующих писателей | `newsbot/store/pglock.py` | Отправная точка блокировок обновления; границы блокировки определить для нового сервиса |
| Диагностика повреждённых ответов | `tests/test_watch_redactions.py`, `test_recheck.py` | Перенести соответствующие регрессионные случаи с учётом новой схемы |

В `watch/redactions.py` реестр содержит десять кодексов. `ON CONFLICT ... DO NOTHING`
сохраняет только первое наблюдение идентификатора редакции. Для общего MCP нужно
замечать и изменение статуса/даты той же редакции, а не только появление нового `redid`.
Источник может вернуть пустую, повреждённую или частично доступную историю; это должно
отражаться в свежести и покрытии конкретного акта.

Рабочая последовательность нового конвейера:

1. По расписанию проверить публикации и каталог редакций; повторно проверить недавнее
   окно и незавершённые задания. Окно определяется свойствами источника.
2. Сохранить исходный ответ, время наблюдения, хеш и происхождение. Повторный ответ
   с тем же содержанием не создаёт новый текст; изменения метаданных сохраняются отдельно.
3. Разобрать структуру, проверить окончание, приложения и страницы; отметить пробелы.
4. Связать акт, редакцию и основания изменения. Не выдавать дату наблюдения или
   `reddate` без проверки семантики поля за дату действия каждой нормы.
5. Подготовить текстовый и векторный индекс новой версии; публиковать их согласованно.
   При сбое чтение продолжает использовать последнюю целую опубликованную версию.
6. Записать событие изменения и его статус, обновить показатели свежести. После сбоя
   повтор не создаёт дубли событий; прежние доказательства сохраняют свои адреса.

Журнал различает публикацию изменяющего акта, появление текста редакции, изменение
метаданных и подтверждённое вступление положения в силу. Это разные события.
Старое доказательство остаётся воспроизводимым; рядом появляется указание на более
новые наблюдения. Юридический вывод автоматически не переписывается.

Нельзя переносить клиентские фильтры newsBot, реестр десяти кодексов, Google Sheets
и рассылки как обязательные части MCP. Новостной отбор по теме не должен удалять акты
из общей базы. Предлагаем выделить нужные адаптеры и проверки в модуль, а не подключать
production-инсталляцию newsBot к чтению пользовательских чатов.

## Упаковка плагина

[OpenAI](https://developers.openai.com/plugins/build/plugins) описывает переносимый
`plugin.json`, `skills/`, необязательный `mcp.json` и совместимые манифесты.
[Claude Code](https://code.claude.com/docs/en/plugins) использует
`.claude-plugin/plugin.json` и поддерживает навыки, агентов, hooks и MCP-компоненты.
Общий текст `SKILL.md` переносим по смыслу, но команды, пути, разрешения и выполнение
проверяющего требуют испытания на каждом хосте.

Предлагаем одну исходную библиотеку процедур, шаблонов и Python-инструментов, из которой
собираются проверенные пакеты для Codex и Claude Code. Возможность единого архива
проверяется отдельно. Пакет без нашего MCP должен устанавливаться и выполнять
документный сценарий без авторизации в нашем сервисе. Настройки подключений хранятся
вне обновляемого пакета; установка не перезаписывает AGENTS.md/CLAUDE.md пользователя.

Из текущего проекта переносим схему известных полей, вычисления через Decimal,
рендер DOCX и структурные проверки. Пример `run_pipeline` работает с одним
синтетическим шаблоном и фиксированным именем результата. Перед использованием в
плагине нужны отдельный CLI, безопасное имя нового файла, контракт шаблона и
проверка конкретного формата результата. Редактирование произвольного DOCX с
сохранением оформления и tracked changes текущим кодом не решено. Это требуемая часть
договорного этапа, поскольку upstream предусматривает DOCX с правками и комментариями.
Для других семейств нужны также PDF на чтение, XLSX/CSV и источники каждой ячейки.

Первый плагин работает в обычной файловой среде агента по выбору владельца. Поэтому
автоматическую псевдонимизацию до первого чтения моделью не обещаем. Защищённый режим
потребует отдельного процесса подготовки, ограничений доступа к оригиналам и проверки
всех каналов. [Прежняя privacy-спецификация](../specs/local-pseudonymization.md)
сохраняется как основа этой будущей работы.

## IDE после самостоятельных модулей

Предлагаем повторно использовать принятый макет как интерфейс третьего модуля.
Его агентный runtime подключает MCP по публичному контракту и исполняет процедуры
плагина через адаптер выбранного хоста. Установленный Claude/Codex plugin нельзя
считать универсальным исполняемым модулем для любого собственного UI: потребуется
либо интеграция с runtime, либо самостоятельный исполнитель тех же процедур.

Варианты: собственный агентный цикл через API моделей или подключение готового runtime
через поддерживаемый SDK. Первое даёт контроль документов и разрешений, второе может
сократить объём собственной агентной логики, но требует проверки совместимости навыков
и условий запуска. Выбор движка документов и оболочки оставляем этапу IDE. SQLite
остаётся возможным хранилищем локального состояния IDE, без обязательства для MCP
или плагина.

## Испытания, которые определят реализацию

- Подключить один read-only MCP в ChatGPT и Claude: вход, вызов, отказ доступа,
  длинный результат, пустая выдача и недоступный источник.
- Построить каталог федеральных актов и отчёт пробелов до обещания полноты;
  проверить первоначальную загрузку отдельно от ежедневного мониторинга.
- Прогнать обновление на повторной публикации, изменении того же `redid`, будущей
  редакции, позднем документе и сбое между разметкой и публикацией индекса.
- Расширить оценку поиска с юристом и отложенной контрольной частью; сравнить
  лексический, семантический и комбинированный поиск без настройки на контроле.
- Установить плагин в чистые профили Codex и Claude Code, выполнить одинаковую
  задачу с отключённым MCP и затем с ним. Отдельно проверить DOCX.
- Измерить CPU/RAM/диск и ежедневную очередь на VPS; первоначальную загрузку отделить
  от online-запросов. Технические испытания начинаются до участия юристов.
- Проверить весь каталог процедур, включая форматы и фоновые задания;
  установка текста навыка не является проверкой его выполнения.

В этой задаче выполнено исследование и обновление документации. Перечисленные
продуктовые испытания предстоят; результаты прежних тестов относятся к прежнему коду.
