# Правовой MCP: бесплатные источники и требования к VPS

Дата: 2026-10-30. Основание: владелец выбрал VPS и исключил платные правовые источники.
Это расчёт для планирования, без покупки сервера и без измерений на VPS.

## Рекомендуемая конфигурация

Для загрузки широкого федерального корпуса предлагается Linux VPS с **8 vCPU,
32 ГБ RAM и 300-500 ГБ NVMe**, с расширяемым диском. GPU на первом этапе не требуется.
Для подключения клиентов и технического пилота с ограниченным объёмом рассматриваем
**4 vCPU, 16 ГБ RAM и 150-200 ГБ NVMe**. Достаточность обеих конфигураций подтверждается
измерениями ниже; это не гарантия вместимости всего законодательства.

| Профиль | Ресурсы для планирования | Назначение и ограничения |
| --- | --- | --- |
| Технический пилот | 4 vCPU, 16 ГБ RAM, 150-200 ГБ NVMe | MCP, PostgreSQL, небольшая embedding-модель, ограниченный updater; массовую загрузку выполнять отдельно от нагрузочного теста |
| Начало работы с широким корпусом | 8 vCPU, 32 ГБ RAM, 300-500 ГБ NVMe | Рекомендуемый исходный размер; лимиты фоновых работ и расширение по фактическому объёму |
| Рост истории и нагрузки | Отдельная БД; 64 ГБ RAM и диск от 500 ГБ как следующий вариант для измерения | Выбирать по размеру рабочего индекса, задержкам и очереди обновлений |
| Первоначальный backfill/OCR | Временный worker либо ограниченный пакетный запуск на основном VPS | CPU/GPU и длительность определяются пробой на реальных страницах; постоянный GPU заранее не арендуется |

Число vCPU у shared-тарифов не описывает гарантированную производительность.
Предпочтителен тариф с гарантированной долей CPU или выделенными ядрами. Проверить
x86-64, инструкции CPU для выбранного inference backend, ограничения IOPS и расширение
диска. ARM можно испытать отдельно; проба на Apple MPS не подтверждает Linux/ARM сборку.

Нужен публичный HTTPS на 443 с доменом и сертификатом. Канал порядка 1 Гбит/с полезен
для загрузки и восстановления, но не является условием самого MCP. Проверить лимиты
трафика и доступность официальных источников из дата-центра, в том числе используемого
ЕБПИ HTTP endpoint на порту 8000. Сбор ограничивается правилами источника, а не только
скоростью канала. PostgreSQL и служебные worker endpoints наружу не публикуются.

## Что работает на сервере

На VPS размещаются reverse proxy с TLS, MCP API, выбранная авторизация, PostgreSQL,
один сервис embeddings запросов, updater, оригиналы документов и мониторинг.
Модель embeddings загружается один раз; несколько web workers не должны незаметно
создавать по копии модели каждый.

ChatGPT/Claude выполняют пользовательское рассуждение вне VPS. Собственного
исследовательского LLM-агента в первом объёме нет. VRAM для большой генеративной модели
в расчёт не входит. Небольшая embedding-модель нужна для семантического поиска.

Массовое OCR, повторный расчёт векторов и построение ANN-индекса работают с лимитами
CPU/RAM и отдельной очередью. При конкуренции за ресурсы сначала выносить эти работы,
затем БД. Единственный VPS остаётся точкой отказа; восстановление из внешней копии
нужно испытать до пилота.

## Основания расчёта

[Прежняя проба](shared-legal-rag-spike.md) включала 3 редакции, 1522 статьи и 2030
поисковых фрагментов. Сохранены 4 719 105 байт исходных snapshots, 4 476 172 байта
corpus JSON; текст статей занимает 3 868 261 байт UTF-8. Это HTML-кодексы, не оценка
сканированных PDF и всего федерального корпуса. Model cache без symlink составляет
493 293 354 байта: размер файлов не является измерением RAM. Прочитаны только ранее
полученные артефакты.

В пробе использована multilingual-e5-small с 384 компонентами вектора. Её
[model card](https://huggingface.co/intfloat/multilingual-e5-small) задаёт предел
512 токенов и префиксы query/passage. Модель остаётся кандидатом; качество на широкой
юридической базе не подтверждено.

По [формату pgvector](https://github.com/pgvector/pgvector/tree/v0.8.7#vector-type)
одно значение vector(d) занимает 4*d + 8 байт. Расчёт ниже относится только к значениям
векторного столбца, без строк таблицы, текста, FTS, ANN, оригиналов и WAL.

| Фрагменты с учётом редакций | Векторы 384, GiB | Векторы 1024, GiB |
| --- | --- | --- |
| 100 000 | 0,14 | 0,38 |
| 1 000 000 | 1,44 | 3,82 |
| 5 000 000 | 7,19 | 19,11 |
| 10 000 000 | 14,38 | 38,22 |

1024 компоненты приведены для сравнения, без выбора другой модели. Число актов
недостаточно: важны длина, дробление и количество редакций. Повторяющийся текст можно
индексировать один раз только с сохранением всех связей и воспроизводимости доказательств.

HNSW дополнительно хранит граф и данные индекса. Он требует больше памяти при
построении, чем IVFFlat; [pgvector](https://github.com/pgvector/pgvector/tree/v0.8.7#hnsw)
рекомендует учитывать maintenance_work_mem. Универсального множителя для всей БД
не принимаем: таблицы и индексы измеряются после загрузки. Точный поиск из прежней
пробы не подтверждает скорость ANN и фильтрацию на миллионах строк.

## RAM и диск

Пример бюджета **32 ГБ RAM**, который нужно проверить по пикам:

| Компонент | Предварительный резерв |
| --- | --- |
| ОС, proxy, MCP, лёгкая авторизация и мониторинг | 3 ГБ |
| PostgreSQL shared buffers | 6 ГБ |
| Сессии БД, сортировки и текущие запросы | 3 ГБ |
| Embedding inference | 3 ГБ |
| Updater и ограниченная обработка файлов | 4 ГБ |
| Кэш ОС, построение индекса и запас | 13 ГБ |

Это расчётный бюджет, не измеренное потребление. Тяжёлая авторизация, OCR или reranker
меняют его. Построение индекса не получает весь запас одновременно с неограниченным OCR.
PostgreSQL предлагает начинать с 25% RAM для shared buffers на выделенной БД; здесь
VPS совместный, поэтому резерв ниже. work_mem расходуется по операциям и соединениям,
а не один раз на сервер. Основание:
[PostgreSQL resource consumption](https://www.postgresql.org/docs/18/runtime-config-resource.html).

В бюджете **300 ГБ диска** можно предварительно отвести 20 под ОС/образы/модель,
80 под БД с индексами, 50 под оригиналы, 30 под WAL/временные операции и 120 под рост,
перестроение и свободное место. Это лимиты планирования: при превышении нужно расширение
до продолжения загрузки. PDF и долгую историю можно вынести в объектное хранилище.
Внешняя резервная копия не включена в эти 300 ГБ. ГБ в тарифе и GiB в таблице векторов
имеют разные единицы.

## Первичная загрузка и ежедневный цикл

Время embeddings равно числу новых фрагментов, делённому на измеренные фрагменты
в секунду. Для 1 млн условные 10/25/50 фрагментов в секунду дают примерно
27,8/11,1/5,6 часа только на векторы. Это сценарии расчёта, не скорость выбранного VPS.
Сеть, OCR, разметка и индексирование добавляют время. Прежние 8,74 секунды на Apple MPS
не переносятся на CPU VPS.

Ежедневный цикл считает embeddings для нового/изменённого текста. Изменение метаданных
не требует пересчёта неизменившегося содержания. Новая версия парсера или модели может
потребовать полного пересчёта с сохранением доступной предыдущей версии; для него
нужны отдельное время и запас диска.

Для CPU можно сравнить PyTorch и ONNX/OpenVINO, затем квантование.
[Sentence Transformers](https://www.sbert.net/docs/sentence_transformer/usage/efficiency.html)
документирует эти варианты. После оптимизации повторяется проверка качества поиска.

## Только бесплатные правовые источники

| Канал | Роль | Известное и следующая проверка |
| --- | --- | --- |
| publication.pravo.gov.ru | Оригиналы и события опубликования | В newsBot есть адаптер с пагинацией и контролем дат; нужен backfill федерального каталога |
| ЕБПИ на actual.pravo.gov.ru | Тексты и метаданные редакций | Живая проба получила редакции ГК; полнота по ведомствам и истории не установлена |
| ИПС «Законодательство России» | Дополнительная проверка каталога и текста | Аудит выявил отличия идентификаторов и ограничения длинных текстов; готовой взаимозаменяемой API нет |
| Портал Минюста | Федеральные акты и сведения об актах ведомств | Бесплатность доступа подтверждена Минюстом; массовая выгрузка и новый адаптер пока не испытаны |
| Официальные сайты органов | Пробелы, приложения и материалы органов | Использовать подходящие адаптеры newsBot; отличать нормативные акты от писем, новостей и проектов |

Основания: [аудит портала](pravo-portal-audit.md), [newsBot](newsbot-sources.md),
[RAG-проба](shared-legal-rag-spike.md),
[описание доступа Минюста](https://minjust.gov.ru/ru/appeals/faq/605/).
Прямое открытие pravo.gov.ru и publication.pravo.gov.ru через web-инструмент в этом
исследовании завершилось timeout. Это не проверка доступности из VPS и не опровержение
прежних HTTP-проб. Массовый доступ и хранение, история, лимиты и устойчивость каждого
канала требуют отдельной проверки.

Платные правовые базы, коммерческие исследовательские API и подписка CoCounsel исключены.
Обход paywall не рассматривается. Ограничение относится к правовым данным; стоимость
VPS, копий и агентного хоста учитывается отдельно. Обязательный платный embedding API
не нужен: исходный вариант использует открытую модель.

Недоступная редакция отмечается как пробел; конвейер пробует другой разрешённый
официальный канал и повторяет загрузку позже. Восстановленная программой редакция
не получает статус официального текста. Бесплатные источники не дают основания
обещать полное историческое покрытие до аудита каталога.

## Проверка перед выбором тарифа

1. Задать каталог и глубину истории. На выборке разных видов актов измерить число
   фрагментов, объём оригиналов и долю страниц, которым нужен OCR.
2. На CPU VPS измерить холодный старт, RSS модели и embeddings запросов/пакетных текстов.
   Записать CPU, RAM, backend, размер batch и пропускную способность.
3. Измерить размер БД/FTS/ANN и время построения. Сравнить ANN с точной выдачей, включая
   фильтр по редакции, чтобы ускорение не скрывало потери.
4. Прогнать 1, 5 и 10 одновременных вызовов, затем вместе с updater. Измерять p50/p95
   от получения запроса до ответа, включая embedding, CPU, RSS, swap, I/O и очередь.
   Целевой предел задержки задать до теста.
5. Проверить ежедневную очередь до следующего цикла, отставание после сбоя,
   резервную копию, восстановление и подключения ChatGPT/Claude.

Расширение требуется при нарушении заданной задержки, очереди больше суток, устойчивом
swap или нехватке диска для следующего индекса/WAL. Предложенный сигнал пересчёта
хранения: свободно меньше 25% либо рост за ближайший месяц исчерпывает резерв.

Юристы позже проверяют применимость и качество результатов. Технический план,
загрузка и ресурсные измерения не ждут разметки юриста; до неё результаты не обозначаются
юридически проверенными. Связанные документы: [MCP](../specs/legal-mcp.md),
[дорожная карта](../plans/active/modular-platform-roadmap.md).
