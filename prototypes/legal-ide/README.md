# Интерактивный макет юридической IDE

**Добавлен рабочий режим с API.** Запустите `uv run python scripts/run_ide.py` из корня
и откройте http://127.0.0.1:8765. Реальный чат, контекст, просмотр исходящего запроса,
замена заданных значений, предложения правок, принятие/undo и отдельный проверяющий.
Подробности, модель, ограничения и проверки: [инструкция](../../docs/runbooks/live-ide.md).
Ниже описан сохраненный автономный режим `file://`, в котором сеть не используется.

Откройте [index.html](index.html) в современном настольном браузере. Сборка, сервер и установка
зависимостей не нужны. Интерфейс на русском, основной макет рассчитан на окно 1440 × 1000.

Это HTML/CSS/JavaScript-прототип интерфейса будущего Windows-приложения. Он не использует
настоящие DOCX/PDF-движки, модели, правовые API или файловую систему пользователя.
Все документы, имена и ответы синтетические. Реальные ключи вводить нельзя; поле отключено.
Состояние хранится в памяти страницы до перезагрузки, запросов к внешним сервисам нет.

## Сценарии просмотра

1. Главный экран: папки, документ и чат. Выделенная правка допускает принятие/отклонение/отмену.
   Пункты 1.1, 4.2 и 7.3 можно редактировать; пункт 7.2 — после решения по предложению.
2. «Запустить демопроверку» показывает замечания отдельного проверяющего. Изменение документа
   аннулирует сценарий: макет явно сообщает, что новый текст не анализируется.
3. «Основание» открывает карточку нормы. Текст закона и редакция не загружены; ложной точной
   цитаты нет. Поиск в разделе источников работает только по двум демонстрационным карточкам.
4. Техническое задание: имитация двух страниц PDF, выделение пункта и добавление в диалог по договору кнопкой «В контекст договора».
5. Навыки (значок звезды слева): инструкция → пример процедуры → демозапуск → сохранение версии.
6. «Все диалоги»: поиск по названию, документу и переписке, дата последнего сообщения.
   Выбор строки открывает документ и восстанавливает чат, черновик и добавленный фрагмент ТЗ.
   «＋» создает отдельный диалог по открытому документу, сохраняя предыдущий.
   При выборе другого документа открывается его последний диалог. История только до перезагрузки.
7. Защита (щит): сравнение исходных вымышленных имен и псевдонимов. Настройки: выбор провайдера
   и модели, без реального соединения. Ctrl/Cmd+K — быстрый переход. «＋» в чате — новый диалог.
8. Экспорт сохраняет текст текущего макета в TXT; это не экспорт Word. Сброс удаляет только
   состояние примера. Отмена старого решения не удаляет последующую ручную правку пункта.

## Проверка

`node --check app.js` проверяет синтаксис. Дополнительный `verify.cjs` требует отдельно
доступных Playwright и Chromium; зависимости Python-проекта он не меняет.
Если Playwright уже доступен через Node resolution: `node verify.cjs` из этой папки.
Иначе задайте `PROTOTYPE_PLAYWRIGHT_MODULE` равным пути установленного пакета Playwright.
Проверка обновляет снимки и [validation.json](screenshots/validation.json).

Проверены 11 групп сценариев в Chromium на macOS: навигация, правки, отсутствие потери ручного
текста при отмене, снятие устаревших замечаний, TXT-экспорт, навыки, настройки, защита и поиск.
Контрольные ширины: 1440, 1280, 960 и 390 px. В прогоне нет ошибок страницы и внешних запросов.
Это не тест настоящей юридической корректности, нативных файлов и исполнения на Windows.

Первый просмотр выполнен в Orca. Для итоговых PNG использован Playwright/Chromium: захват
расширенного viewport встроенного браузера дал артефакт изображения. Итоговые снимки просмотрены.

## Обновление интерфейса 21.10.2026

Нейтральная темная палитра, упрощенная боковая панель, менее заметные рамки,
крупнее текст документа и переписки. Раздел диалогов занимает всю рабочую область.
Изменения реализованы в автономном и API-режимах, без новых зависимостей.

`verify-dialogues.cjs` проверяет историю в обоих режимах; требует того же Playwright
и сервера на 8765. Все ответы API заменяет фикстурами. Проверяет отдельные диалоги
по одному документу, черновики, поиск, страницу PDF, явное добавление фрагмента ТЗ,
устаревшие предложения, отмену в своем диалоге, второй анализ, ошибки, смену контекста во время
запроса, отзыв старого preview, экранирование и очистку после перезагрузки.
Снимки истории обновляются этим скриптом. Реального обращения к модели нет.
