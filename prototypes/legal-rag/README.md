# Проверка общего правового RAG

Изолированный эксперимент с публичными текстами ГК I и IV, PostgreSQL/pgvector и
`intfloat/multilingual-e5-small`. Проверяет загрузку редакций, разметку статей,
адреса фрагментов и поиск. Рабочий IDE-прототип и зависимости корневого проекта
не меняет. Результаты относятся к небольшому корпусу и пробным запросам.

## Устройство

`probe.py fetch` делает шесть публичных запросов ЕБПИ: метаданные двух актов,
тексты трёх редакций и отдельную пробу метаданных будущей редакции. При ошибке
прогон прекращается. Исходные ответы сохраняются по SHA-256 во внешней рабочей
папке; корпус записывается только после успешной обработки всех выбранных текстов.
HTTP и контрольная сумма не подтверждают подлинность источника.

Разметка сохраняет надстрочные номера, включая составные, например `123⁷⁻¹`.
Внутренний номер такой статьи: `123.7-1`. Неизвестная разметка надстрочных индексов,
неразобранный заголовок статьи, повтор номера или отсутствие ожидаемого окончания
вызывают ошибку. Статьи без названия сохраняют собственные границы. Источник может
заменить отменённую заключительную главу явной пометкой о диапазоне статей;
эта пометка сохраняется в метаданных редакции. Проверка окончания не доказывает
побуквенную полноту всех промежуточных положений, таблиц и приложений.

ID статьи включает акт, редакцию, хеш ответа и версию извлекателя. Внутри статьи
создаются фрагменты до 384 токенов с перекрытием в 64 токена и смещениями в
извлечённом тексте. Полный текст статьи доступен отдельно. Проверяется, что
вход с заголовком помещается в 512 токенов модели без скрытого обрезания.

Поиск сравнивает:

- PostgreSQL FTS: русская нормализация, OR по лексемам вопроса, `ts_rank_cd`;
- точный косинусный поиск pgvector по embeddings;
- объединение двух списков статей через RRF с параметром 60.

В каждой выдаче до 50 уникальных статей. Перед ранжированием SQL ограничивает
редакции явным списком ID. Для обычных проб берётся флаг `actual` источника;
отдельная SQL-проверка получает прежнюю редакцию. Действие нормы на дату отношений
клиента этим не устанавливается. Приближённого векторного индекса, reranker,
генерации ответа и агента-проверяющего в эксперименте нет.

`queries.json` содержит 12 заранее записанных пробных вопросов и ожидаемые статьи.
Это проверка попадания конкретной статьи, без независимой юридической разметки
и без полной оценки всех релевантных результатов. `hit_at_5` означает долю
вопросов с ожидаемой статьёй в первой пятёрке, `mrr_at_50` учитывает её позицию.

## Повторение

Нужны Docker, uv и Python 3.12. Выполнять из корня репозитория. База запускается
на loopback, без подключения пользовательских папок; её данные исчезают после остановки.
Фиксированный адрес эксперимента: `127.0.0.1:55439`, БД и роль `rag_spike`.

```bash
uv sync --locked --project prototypes/legal-rag --python 3.12

docker run --detach --rm --name ai-legal-rag-spike \
  --publish 127.0.0.1:55439:5432 \
  --env POSTGRES_DB=rag_spike --env POSTGRES_USER=rag_spike \
  --env POSTGRES_HOST_AUTH_METHOD=trust \
  --tmpfs /var/lib/postgresql/data \
  pgvector/pgvector@sha256:ac08538c6f8b9904c33c8224c5e5706dbe760aca29db1d096972b4052c22a75d

uv run --locked --project prototypes/legal-rag python prototypes/legal-rag/probe.py \
  fetch --output /private/tmp/ai-legal-rag-spike

HF_HUB_DISABLE_IMPLICIT_TOKEN=1 HF_HUB_DISABLE_TELEMETRY=1 \
  HF_HOME=/private/tmp/ai-legal-rag-spike/huggingface \
  uv run --locked --project prototypes/legal-rag python prototypes/legal-rag/probe.py \
  evaluate --output /private/tmp/ai-legal-rag-spike \
  --model-revision 614241f622f53c4eeff9890bdc4f31cfecc418b3

docker stop ai-legal-rag-spike
```

После запуска PostgreSQL должен закончить инициализацию до этапа `evaluate`.
При повторении модель и embeddings берутся из кеша той же рабочей папки.
Можно явно выбрать `--device cpu`, `mps` или `cuda`. Скорость embeddings зависит
от устройства; время SQL-поиска не включает получение embedding вопроса.
Каждый прогон создаёт новую случайную схему во временной БД и не удаляет другие схемы.

Артефакты в рабочей папке: `snapshots/`, `sources.json`, `corpus.json`,
`embeddings-*.npy`, `results.json`, кеш модели. Сырые тексты и веса не добавляются в Git.
После изменения извлекателя команда `reparse --output <та же папка>` пересчитывает
корпус из сохранённых снимков, проверяя их SHA-256, без повторной загрузки источника.
Результаты прогона 30.10.2026: [отчёт](../../docs/investigations/shared-legal-rag-spike.md).

## Проверки кода

```bash
uv run --locked --project prototypes/legal-rag python -m pytest \
  -c prototypes/legal-rag/pyproject.toml prototypes/legal-rag/tests
uv run ruff check .
uv run pytest
```

Тесты используют синтетические фрагменты. Проверяются надстрочные номера,
неподдерживаемая разметка, HTML-комментарии, границы статей, пометка отменённой
главы, подмена цитаты и редакции, недопустимый диапазон, стабильность ID и RRF.

Источники технических решений: [pgvector и гибридный поиск](https://github.com/pgvector/pgvector#hybrid-search),
[FTS PostgreSQL](https://www.postgresql.org/docs/current/textsearch-controls.html),
[карточка модели](https://huggingface.co/intfloat/multilingual-e5-small).
Предшествующий [аудит ЕБПИ](../../docs/investigations/newsbot-sources.md).
